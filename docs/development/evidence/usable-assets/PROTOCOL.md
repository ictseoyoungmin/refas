## Execution and observations

1. Record baseline topology, weights/hierarchy, declared intended use and
   source-visible features before choosing a representation.
2. Fix the budget and tested motion/character before selecting an optimized
   candidate. There is no universal game/film polygon threshold.
3. Build useful retopology, fit/skin or articulated motion with ordinary bpy.
   Keep detailed source, failed candidates and local-edit mappings.
4. Inspect original sources and actual whole/detail/inside/wireframe renders.
   Hold before/after camera/light/size/sample settings fixed for like states.
   A posed on-character view and a neutral garment are different observations;
   source cameras remain unregistered unless actually calibrated.
5. Check evaluated and imported topology, actual surface/anchor relationships,
   and intermediate motion. Record intentional openings and contact exemptions
   by actual part and reason. Do not convert a tool warning into silent PASS.
6. Reopen native and GLB, repeat a meaningful local edit/restore, and execute
   exported animation in installed Godot. Record actual consumer version and
   behavior. Headless playback is not a GPU image/performance benchmark.
7. Freeze the selected candidate and obtain independent source/render/code
   review before crediting each acceptance criterion.

Use the new small Blender mesh-observation helper when appropriate; it does
not decide source intent or global game readiness. Triangle reductions,
successful parsing and object counts alone do not close practical criteria.
