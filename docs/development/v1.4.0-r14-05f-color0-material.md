# R14-05F — COLOR_0 material provenance and appearance safety

Status: IMPLEMENTATION CANDIDATE; CI and real-GLB PBR preview acceptance
required. This is a material-handling slice, **not** R14-05 source-resemblance
certification or R14-06 trusted external-renderer integration.

## Origin of this change

The user-supplied Monster Bed v4 GLB (original SHA-256
`30f8e135a34470366780b9b600040dff823171dfe857e7e4ab681c520a95f8d7`)
contains **901,664 indexed triangles**, of which 512,000 come from
`PetBed_Fur_mesh`. The fur primitive has a `COLOR_0` RGB VEC3/FLOAT
attribute with 320,000 vertex colors. Previously the loader discarded it,
and the CPU diagnostic albedo substituted a uniform 0.7 gray as
`FurMat` has no `baseColorFactor`. This is an actual loss of the source
appearance signal, not harmless synthetic-raster approximation.

## Intended contracts

- The common GLB loader preserves `Primitive.vertex_colors` as *linear*,
  per-vertex RGB. Decode both float VEC3/VEC4 and glTF normalized unsigned
  byte/short encodings. Missing/invalid or nonfinite values cannot silently
  become uniform color. When a primitive has COLOR_0 but lacks the glTF
  baseColorFactor, its material color is **white 1.0** (glTF default) rather
  than the portable backward-compatible 0.7 fallback for old/no-COLOR_0
  assets. The source GLB is never rewritten or decimated.
- Independent PBR `render_pbr.py` interpolates the per-vertex RGB using
  already-calculated **perspective-correct pixel weights**, multiplies
  by the material baseColorFactor and any supported texture, shades as
  before, and uses the piecewise sRGB output transfer for COLOR_0
  appearance. Opaque VEC4 with alpha not identically 1 requires a distinct
  alpha/blend pipeline and is **typed refused**, not silently ignored.
  Neutral-clay explicitly discards source materials by design.
- Portable diagnostic `render_glb.render()` **refuses** `beauty` and
  `albedo` for COLOR_0 because it has constant per-triangle shading and
  would falsely substitute a flat color. Its geometric normal/object-ID
  views remain unaffected; existing no-COLOR_0 replay semantics unchanged.
- Shared Numba `render_cpu_visibility.render_bundle()` rejects any
  `albedo` request on a COLOR_0-bearing primitive **before** raster/cache
  load or write. Only `normal` and `object-id` passes may render that
  asset in this CPU diagnostic backend. Cached winner/depth/normal buffers
  do not have perspective-correct color weights; never claim they encode
  color fidelity.
- GLB decoded memory budget includes the new color arrays; source paths,
  cache identity, renderer trust authority and geometry depth/winner logic
  remain unchanged. The PBR report explicitly declares
  `vertex-color-0` as supported only when the loaded original material
  has such an attribute. No GPU/external certification is implied.

## Adversarial acceptance

Focused new regression `tests/test_render_cpu_vertex_color.py` checks:

1. Real embedded-GLB accessor with float COLOR_0 and absent baseColorFactor:
   decoded linear RGB survives, factor defaults to white; portable Albedo
   refuses without leaving a misleading PNG.
2. Normalized u8 RGBA decodes using `1/255`; nonopaque VEC4 source
   alpha is not silently discarded in PBR.
3. An independently computed different-depth triangle pixel produces
   **perspective-correct RGB × baseColorFactor × sRGB** rather than
   affine RGB, to image-byte tolerance.
4. Shared CPU diagnostic albedo refuses **before cache creation and
   without corrupting** a pre-existing geometric winner/depth cache.
   Both geometric normal and ID passes remain available.

## Remaining

- Test the original Monster Bed without public source-byte upload under
  a provisional diagnostic frame. Confirm the PBR Color_0 path produces
  authored dark-brown fur rather than a gray material, with source SHA
  and image bytes bound in a local diagnostic record.
- `render_pbr.py` skips near-plane-straddling triangles today; this
  slice does not make that existing renderer behavior authoritative.
  Multi-view registration/PBR/reference resemblance are **separate**
  gates that remain open, requiring a source-photo camera registration.
- R14-06 trusted external backend plan still needs its own signed
  capability/interface review. This in-process PBR capability must not
  be relabeled as a trusted external renderer.
