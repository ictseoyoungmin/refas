# Bounded fitting and discrepancy evidence

RefAs now exposes owner-local fitters for the high-impact loop:

- `createCameraFitPlan` / `fitCamera` belong to `spatial-hypotheses` and search bounded camera variables without changing geometry. A plan may declare perspective and orthographic projection candidates; the bounded evaluator interleaves them so each declared hypothesis receives trials.
- `createPoseFitPlan` / `fitPose` belong to `assembly` and may change only parent-local transforms. The fitter verifies that mesh/accessor bytes remain identical. Node-local transform bindings are parsed from their explicit `translation|rotation` suffix so dotted node identifiers cannot absorb the transform property.
- `createOrientationPoseFitPlan` / `fitOrientationPose` extend assembly-owned pose search when endpoint/longitudinal-axis agreement is insufficient. A terminal facing or roll mismatch reopens the smallest evidence-cited parent→child chain and evaluates correlated parent-local edits while preserving mesh bytes and the existing structural hard barrier. The bounded candidate set includes both coordinated and mixed-sign parent/child rotations, so a correct terminal frame is not restricted to rotating every link in the same direction.
- `createMacroFitCoordinatorPlan` / `runMacroFit` sequence camera, pose, then shape stages. The coordinator records reports but cannot choose a finding owner or certify.
- `createAppearanceFitPlan` / `fitAppearance` and `createLightingCalibrationPlan` / `fitLighting` alternate illumination and material calibration after geometry is frozen. Every trial must report the frozen geometry and frame digests.

`createPerceptualDiscrepancy` supplies deterministic, model-free image evidence: silhouette IoU, boundary distance, edge disagreement, occupancy, dimensions, coarse luminance/color, negative-space masks, and optional segment masks. `createOrientationDiscrepancy` complements those raster measurements with primary-axis, facing, lateral, and twist residuals, so two candidates with the same silhouette axis can still disagree materially in 3D orientation. Orientation loss is derived from the validated discrepancy artifact rather than accepted as an unbound caller score; every discrepancy must bind the exact candidate SHA-256, source digest, and orientation-evidence digest before the candidate can rank. These measurements rank candidates and surface contradictions; they never become a universal visual-fidelity threshold or a certification gate.

The orientation contract is deliberately asset-class neutral. Core vocabulary records camera-relative facing, visible-plane evidence, generic clockwise/counterclockwise twist, ambiguity, and full-frame residuals; anatomy-specific semantics such as pronation/supination and robotics-specific actuator or joint semantics belong outside the general Core contract. A large primary-axis disagreement remains valid bounded discrepancy evidence instead of making frame comparison throw, while axis-only input still fails closed when roll is underdetermined.

`createLandmarkCage`, `createLongitudinalGuide`, and `createSectionProfileLoft` form the reusable construction backend. A section loft supports asymmetric width/depth, arbitrary profiles or superellipses, twist, offsets, flattening, taper, and semantic section parameters. `createRepresentationCapacityReport` turns an obligation the backend cannot express into an explicit representation blocker; tessellation alone cannot clear it.

`createBenchmarkMatrix` binds external raw-source paths by digest and records baseline/final assets, diagnostics, fitting ledgers, findings, rollback evidence, visual review, and (only when justified) a certificate. The benchmark example can attach these records from project roots without copying external sources. Generic capability closure requires at least two materially different benchmark classes.
