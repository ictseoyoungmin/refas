# RefAs v1.2.1 — S02b2b: Host precommit and upstream source-selected camera authority

Parent: [#272](https://github.com/ictseoyoungmin/refas/issues/272); base `develop/v1.2.1@85ad77f2eb2c71d01912c6c286b720a837f7e92a`.

## Prior failure

S02b2a prevented an invalid final source-bound certification from passing readiness/certificate/audit, but `commitCheckpoint(whole-object-certification)` could still return a persisted checkpoint and runtime PASS gates for a forged source/render image. A worker could also produce a deterministic correct image for **its own** registered canonical hero camera (and matching report digest), even if the source-bound **upstream** `spatial-hypothesis-set` had selected a different high-impact camera before reconstruction.

## S02b2b implemented

Before evaluating runtime gates or writing any final checkpoint, nonfixture `commitCheckpoint` now:
- Requires exactly one independently claimed PASS visual review in the prospective stored artifacts.
- Reuses the current candidate authority/final-candidate SHA from the immutable parent lineage.
- Runs the existing `inspectRegisteredComparison` against the prospective artifacts, checking exact registered comparison/source/render report and GLB digest bindings, then running the installed S02b1 independent GLB/camera/PNG pixel replay.
- Resolves a prior-to-shape `spatial-hypotheses` checkpoint's `spatial-hypothesis-set` via the existing immutable artifact verifier. Validates source SHA, scope, original source citation for every camera, selected hypothesis, and **all competitors falsified**. The selected projection must be a supported square-perspective hero and its position/target/orthogonal-up/fovY must equal the stored registered hero's camera; merely matching an authored `registrationDigest` is insufficient.
- Rejects a forged or missing artifact, a replay mismatch, or a camera difference as `prospective source-bound certification REVIEW_REQUIRED` **before runtime PASS gates, checkpoint file, state head, or certification**. Contract fixture authority remains an explicit test exception. Final readiness/issue/resume/audit share the same upstream source-camera check, so an older stored certificate cannot carry a camera-authorship loophole.

## Adversarial checks

- Real GLB/registered hero positive still commits and certifies.
- Missing canonical camera is rejected before state head/ID changes.
- Actual PNG altered with re-signed frame/report SHA is rejected before state head/ID changes.
- Even independently replayable rendered hero from a **different** camera (report/hash internally consistent) is rejected by the frozen prior source selection; after failure state head/ID unchanged.
- Existing grossly wrong source-camera/realized projection test now fails at prospective admission, not only at later certification.

## Deliberate remaining limitations

No exact raw photo mask recomputation from the current trusted GLB render occurs here; S02b2c must independently rerun the source-photo/registered-hero pixel comparison and treat ambiguous segmentation as INSUFFICIENT, never PASS. The spatial-hypotheses input is an original-source-cited prior observation, not a proof that its semantic camera choice is visually correct; upstream S01/S03 still must verify actual source truth and reject mistaken interpretations. There is no one-image likeness PASS, and the overall P0 #272 remains OPEN. Main stable v1.2.0 stays untouched.
