One further runner reproducibility defect: candidate stages currently use the latest --input-blend argument, while original_inputs only records the first invocation's path/hash. A different native argument can silently enter the old before/after comparison even if the old path remains unchanged. Before any candidate mutation, require the supplied native hash to equal the recorded baseline native hash, or always use the frozen captured baseline. Same bytes at a moved path may be accepted; different bytes must start a new root. Current executions use the intended source, so retain them unchanged.
