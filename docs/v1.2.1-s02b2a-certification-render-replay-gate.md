# RefAs v1.2.1 — S02b2a mandatory source-bound certification render replay

Parent issue: [#272](https://github.com/ictseoyoungmin/refas/issues/272). Base: `develop/v1.2.1@815ac990513f68cd38b56c8ae6331438a25516f3`.

## Defect

The published S02b1 `verifyRegisteredRenderReplay` independently re-renders current GLB and frozen canonical camera, but it was **not called** by normal certification readiness, certificate issue, restored certified-project audit, or review-guidance paths. An operator could supply mutually consistent source/GLB/registered comparison/render report SHA references, claim a source comparison PASS, and omit the actual rerender proof.

## S02b2a implemented boundary

At the existing `checkpoint-store.mjs → inspectCertificationHead → inspectRegisteredComparison` route, **every nonfixture independent passing visual review** now requires exactly one `canonical-object-frame` stored in its current certification head, current candidate GLB matching the trusted final candidate from `resolveFinalSpatialContinuityFromLineage`, report-bound registered hero PNG, and a supported exact backend. The source frame must bind the current registered comparison digest. The installed `verifyRegisteredRenderReplay` checks actual current GLB+frame bytes and independently recreated exact hero PNG SHA and camera identity. Any missing or mismatched input adds typed `trusted source-bound GLB/render replay REVIEW_REQUIRED` and refuses certification readiness / certificate, while `resumeProject` routes to existing visual review and `auditProject` checks the same verification for already certified projects. The explicitly verified internal contract fixtures stay exempt; no user-selectable acquisition string bypass.

S02b1 renderer hardening for mandatory callers: infer square output size from encoded PNG header (bounded 32–1024px) and **freeze the hash-verified GLB and canonical camera byte snapshots** into the internal temporary render directory before launching Python to avoid pathname time-of-check/time-of-use races.

Test migration: earlier nonfixture VC06/VC07 source-based certification tests used literal text bytes as final `hero.png` and a fake render report with a Three.js label. Preserve their separate PBR/visual-review test artifacts and create an actual 96px registered portable GLB hero + report + canonical source camera specifically for registered comparison. The real-source positive remains certified and audit-valid, while missing canonical camera and coherent changed PNG/report SHA must now refuse readiness and certification.

## Explicitly incomplete

**S02b2a** is a mandatory **certification/readiness/audit** replay of the *reported* registered frame, not yet guaranteed to occur **before the prospective checkpoint is committed** or before worker comparison is generated. The camera artifact is stored with the current certification head and tied to its registered-comparison digest; **it is not yet independently proven to originate from the frozen primary-source spatial-hypothesis selection**. This trust gap is S02b2b (Host precommit and selected-camera lineage) and S02b2c (recompute S02a from raw source pixels and actual trusted renderer pixels rather than accepting author-reported perceptual metrics). A passing render provenance digest never equals a resemblance PASS. Single-view IoU stays disabled.
