binning step. The next optimization should first profile setup and geometry
transforms, not introduce BVH or cache just because such methods exist.

## Same-CPU 500k: all 12 tile × worker configurations passed exact parity

Each configuration ran three warm repeats. The table is median all-pass
wall time, **not** raster-only wall time.

| Tile size | 1 thread | 2 threads | 4 threads | 8 threads |
|---:|---:|---:|---:|---:|
| 16 | 168.224 ms | 158.616 ms | 163.211 ms | 161.990 ms |
| 32 | 168.646 ms | 162.162 ms | **159.941 ms** | 159.010 ms |
| 64 | 164.338 ms | 163.856 ms | 162.413 ms | **155.915 ms** |

The 500k baseline and all 11 alternatives matched **exact SHA-256** for
Normal, Object-ID and Albedo pixel arrays, float64 depth and int64 winning
triangle IDs across all three samples. `coveredPixels=9428`,
`preparedTriangles=500000`, no source geometry silently deleted.
At 1M, `preparedTriangles=1000000`, `coveredPixels=10880`.

The 8-thread cases may oversubscribe the 4 logical CPUs. Their single-runner
differences (best 155.915 ms vs baseline 159.941 ms) are small relative to
the setup cost and should not be represented as a general 8-thread
performance advantage without statistically powered reruns.

### Bounded pixel work (not a speedup multiplier)

The 1M input measured 1,140,459,520 possible old whole-tile sample locations
but only 6,088,522 conservative triangle-rectangle locations examined by
R14-05A, about **187× fewer candidate locations**. This is an operation-count
reduction, **not** a measured 187× elapsed-time acceleration. At this
density, the dominant remaining cost is geometry setup.

## Claim restrictions and next work

- **Supported:** 1M real positive-area triangles rendered three passes
  under a 4-thread diagnostic profile in ~321 ms warm median on this
  particular 4-logical-CPU host, with exact winner/depth/pass parity
  on 12 configurations at 500k.
- **Not supported:** Source-image resemblance, certified 8-view/PBR,
  actual user Monster Bed GLB acceptance, GPU equivalence, universal
  scaling or a 10-minute production SLA. Samples are synthetic Hero,
  160×160 only.
- **R14-05E:** Target the measured camera transformation + compiled
  setup stage, preserve source-bound geometry and top-left/depth/winner
  semantics, and retest with an identical GLB and canonical frame SHA.
  Limit changes to a safe optimization with measured before/after.
- **Before R14-05 closure:** acquire/locate the genuine Monster Bed
  GLB and its registered canonical frame and run the current renderer.
  Full PBR, high-resolution and canonical multi-view authority are
  separate R14-06+ tasks. If unsupported, emit typed limitations
  rather than reducing source geometry or granting a certificate.
