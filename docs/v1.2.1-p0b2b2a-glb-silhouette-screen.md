## What this catches that P0b2b1 could not

Prior implementation verifies primary source SHA, camera selection, real-GLB anchor re-projection, source-visible macro anchor coverage and neutral-clay evidence. A worker can still put the right anchor at the right pixel while the **entire head/torso/whole mesh is a very different screen-space size or sits in a wrong location**. An early `PROCEED` therefore was not a whole silhouette check.

This slice adds a conservative **contradiction screen** to the actual source-bound `shape-reconstruction→surface-topology+` installed admission. It requires at least one *closed, original-primary-source-cited macro outer contour* in the observation checkpoint. It then recomputes the frozen candidate GLB's **actual mesh POSITION vertices through parent/child GLB transforms and the previously selected camera**—never caller-authored model projections or a 2D named anchor—for normalized 2D min/max bounds. Unsupported/sparse/malformed POSITION, clipped or behind-camera geometry, zero projected area and absent contour mean `REVIEW_REQUIRED`, not PASS. Recorded current source contour vs actual GLB screen extents are compared for gross width/height (outside a conservative 0.45–2.2 relative screen band) and frame-center difference (above 0.16 normalized units); strong discrepancies return `REWORK` before downstream accepted detail, without allowing otherwise-good registration scores to suppress them. The screen checks **bounds**, not polygon IoU; it cannot upgrade Reference Fidelity to PASS. Single-view IoU remains forbidden as a gate certificate.

## Controls and evidence

- Current source SHA + frozen typed reference geometry and source citation, frozen actual GLB CAS SHA and canonical selected camera from previous P0a–P0b2b1 requirements.
- Existing `verifyRealizedProjection` and typed `findingsFromRealizedProjection` execute first so negative camera/anchor mismatch retains the more specific owner.
- Input mesh is evaluated from GLB bytes using parent-to-child transform and bounded memory, max 2,000,000 vertices. Contradictory source outer contour, omitted contour and offset contour negative tests, unchanged prior true-positive single-box macro fit, plus installed VC08/certification fixture migration.
- Prior normalized source-space contours in synthetic fixtures were not representative of actual fixed box/prism extent; migrated to meaningful projected geometry values. This does **not** add actual photo pixels to synthetic fixtures.

## Explicit unproven requirements (P0b2b2b)

A manually authored source contour can still be wrong; raw source-image pixel interpretation is **not independently verified** by this slice. A projected all-vertex bounding rectangle is not an occlusion-aware rendered silhouette (convexities, gaps, holes, hair outlines, shoulders and meaning of facial parts can be wrong). Actual photo-vs-registered render image/mask/edge/negative-space and section comparison; source-grounded camera alternatives independently adjudicated; trusted findings `spatial-hypotheses` vs `shape-reconstruction` typed reopen and downstream invalidation; adversarial head yaw/face size/shoulder-depth mutation tests remain parent #272 acceptance. Self-reported evidence cannot overrule source. QA-03 #271, mandatory aggregate final QA #265, external #235/#250 independently open. No Reference Fidelity or Game Ready claim.
