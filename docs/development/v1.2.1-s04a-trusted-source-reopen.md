# RefAs v1.2.1 — S04a installed source re-evaluation → typed upstream reopen

Parent #272. Scope: a recovery/reevaluation bridge for existing source-observable head, face, body and camera contradictions; **not** full S04 or release approval. Implemented at `checkpoint-store.mjs`: `reopenFromTrustedSourceAdmission(root,{scopeId,expectedHeadId})`.

## Security model

The operation **does not accept a worker-supplied finding, checker status, source digest, model digest, recovery capability or positive PASS**. It loads actual project state/head, rejects fixture projects and active edit, reconstructs current lineage and re-runs the installed `ensurePrerequisites(...,'surface-topology')` admission. This invokes the already enforced independently decoded original source image, exact frozen source-geometry, selected camera hypotheses, signed GLB replay, segment orientation, source profile, occlusion and whole silhouette.

Only after the installed validator detects a real contradiction does it map the known runtime failure class into the existing `normalizeFinding → routeFinding → reportFinding` decision and restoration pathway. Camera selection mismatch / source-camera orientation: `spatial-hypotheses`. Actual candidate GLB part orientation / observed macro mass / visible part-depth mismatch: `shape-reconstruction`. Missing or ambiguous source evidence, other errors: **REQUEST_REVIEW** with `evidence-insufficient`, not speculative destructive rollback. Exact source+shape GLB+signed projection refs come from the current lineage, never caller payload.

The report API additionally allows an **optional expectedHeadId compare** and refuses to act on a changed head. This is not a global transaction lock; concurrent, independent writers still require host serialization. No change to the already available public `reportFinding` contract when the optional compare is absent.

Trusted rerun with no detected contradiction returns `NO_DETECTED_CONTRADICTION`, **never** reference-fidelity PASS. This is a bounded negative check, not independent human/photo semantic recognition or QA-01 whole-object final authorization.

## Verification requirements

- Real nonfixture source project with actual GLB wrong macro part long-axis: typed `silhouette-mismatch` routes to `shape-reconstruction`, restores pre-shape checkpoint bytes, invalidates accepted surface/assembly/appearance/render/review/certification, preserves historical rejected snapshots.
- Wrong frozen camera bound to a valid GLB: typed `camera-hypothesis-mismatch` routes to `spatial-hypotheses`, invalidates shape and descendants.
- Hidden/inferred macro source: review only, without inventing geometry or camera certainty; head unchanged.
- Correct observed/GLB projection: no state mutation and cannot authorize positive fidelity.
- Stale expected head fails before evaluation and caller extra finding cannot override installed runtime classification.
- Existing checkpoint-regression suite already tests routes from accepted downstream assembly to upstream and certification invalidation. New S04a tests bind the *actual installed source admission* to that existing route.
