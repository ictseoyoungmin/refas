# RefAs v1.3.0 release readiness

## Scope
Production-oriented agent guidance, adaptive observation and evidence utility, selective PBR review, historical source/evidence preservation, and v1.2.1 CLI compatibility. Retain published runtime source-bound claim authority and all current QA obligations.

## Required exact integration gates

- [ ] Node 20, 22, 24 full regressions on the candidate integration HEAD
- [ ] Fresh installed skill and plugin discovery checks, independent of repository root
- [ ] Complete wing-cover/geometry/assembly/PBR dogfood and final release audit on a `[full-qa]` development push
- [ ] npm package/Claude/Codex/plugin metadata/runtime version match; changelog and README describe correct boundaries
- [ ] evidence original/source-manifest hashes, immutable history, tombstone reassessment, and legacy CLI positive/negative tests
- [ ] failure-injected PBR publishing recovers prior report, frames, previews and optional board
- [ ] full release-branch review and exact HEAD checks before a PR targeting `main`

## Product acceptance

- [ ] Inspectable actual Arcane Chest input-source SHA, before/after native project and GLB SHA, registered capture parameters, and consistent multi-view before/after renders.
- [ ] A credible whole volume with closed intended parts, shared profiles and realistic attachments. Report geometry validity separately from visual resemblance and game suitability.
- [ ] Independent external worker or controlled A/B comparison documents what, if anything, improved. The available eight-view presentation image is encouraging but does not establish this alone.

## Version policy

Public evidence --image invocation remains supported through a dedicated compatibility-only adapter that preserves the v1.2.1 manifest structure, file names, and source primacy. New usage defaults to request-scoped analyses and separate assessed utility. Semantic contract IDs ending /v1 remain stable; application version is 1.3.0.

Version 1.3.0 promotion is contingent on verification and review, not on changing the version number. A merged development branch is not a published release.
