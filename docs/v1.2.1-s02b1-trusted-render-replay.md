# RefAs v1.2.1 — S02b1 trusted GLB-to-render pixel replay

Tracking: [#272](https://github.com/ictseoyoungmin/refas/issues/272). Integration baseline: `develop/v1.2.1@75111abf882d83d7dd53e5ca3b8043b4099365ee`.

## Failure the current comparison still misses

S02a compares the pixels of an encoded original photo to the image bound to a registered render report and catches spatial occupancy or negative-space discrepancies missed by equal-area and equal-bounding-box metrics. However, a worker may replace the claimed render PNG and **re-sign its SHA in its own report** while the exact GLB geometry is different. The earlier linkage proves internally consistent bytes, not that the claimed frame was actually rasterized from the GLB.

## Implemented independent authority

The installed JS public API `verifyRegisteredRenderReplay` resolves **project-contained current files**, bounds input bytes, and verifies the current authoritative candidate SHA plus claimed hero SHA. It requires the `refas.canonical-object-frame/v1` frozen registered `hero` camera with its `registrationDigest`; only the installed `RefAs Portable Rasterizer/1.0.0` backend is eligible. Unsupported renderers are rejected rather than trusted by label or silently substituted.

It then invokes the **installed** `render_glb.py` in a fresh deterministic independent process with the exact GLB and frame files, compares replayed actual hero PNG pixel SHA, full camera parameters, canonical frame digest, source-registration digest, and realized candidate SHA to the claimed report. Files and temporary renders are not accepted from user-supplied paths outside the project. Missing Python/dependencies, changed GLB, forged frame, changed camera and malformed input do **not** produce a render integrity PASS. The temporary independent images are deleted after verification.

Returned `claimScope` is strictly `render-provenance-only` with `cannotAuthorizeReferenceFidelity: true`, **not** a resemblance certificate. It does not derive user-visible source contours from a claimed artifact.

## Positive and adversarial regressions

Deterministic actual GLB raster positive plus fully re-rendered independent exact PNG SHA and source-camera binding. Negative 1 mutates **the actual GLB geometry** while updating current candidate and report SHA yet retaining the old claimed hero PNG: renderer replay must detect the difference. Negative 2 edits a real PNG and re-signs both its own file SHA and render-report frame SHA. Negative 3 changes the source-selected hero camera. Negative 4 omits registration binding. Negative 5 traverses out of project or spoofs renderer backend. These are *real geometry and real image* replay tests, not just unit-json validators.

## Exact limits and follow-on

This is **S02b1 independent verifier implementation**, not yet mandatory certification or Host gate. The caller must pass the current authoritative GLB digest and genuinely frozen source-selected camera; a malicious caller could otherwise select a different plausible camera. **S02b2** must bind the immutable trusted camera and current candidate from the canonical checkpoint lineage and invoke this verifier in every nonfixture positive visual review/certification path, with absent/wrong renderer returning `INSUFFICIENT/REVIEW_REQUIRED`. Existing user-provided render reports may require migration. S03 independently observes original source macro semantics/occlusion and genuine GLB mutations. S04 ensures typed upstream invalidation and rework.

For real screenshots/reference photographs, a successful exact render replay only proves image provenance, never likeness. An ambiguous single view must not yield automatic Reference Fidelity PASS. Existing S02a pixel-shape discrepancy works on registered frames, but feeding **trusted replayed** pixels into it remains S02b2 integration. Parent #272 remains OPEN and stable main v1.2.0 unchanged.
