# Garment and automail validation protocol

The user selected the existing uniform-jacket sheet and the new AURIX automail
sheet on 2026-11-22 (Asia/Seoul). This checkpoint exercises the same production
workflow on continuous cloth and segmented rigid mechanisms. It retains the
previous jacket comparison unchanged.

## Two distinct tasks

| Task | Starting state | Purpose |
|---|---|---|
| Garment refinement | Previously delivered editable jacket with shared armholes | Informed correction of visible cloth transitions, folded collar/lapels and appearance; isolated cuff edit and exact restoration |
| Automail creation | Only the user's complete design sheet | Fresh construction, a service-panel edit, sampled rigid-joint movement, reopening/export and restoration |

Garment work is a continuation with known defects. It is not a fresh independent
attempt or evidence of generalization. The fresh automail authors receive the
raw source and task-local requirements without another author's geometry or
verdict. The production author starts from a frozen copy of the revised skill;
the ordinary Blender control reads no RefAs guidance and the legacy control
uses the fixed `a29bcc42` skill. Their object representations are their choices.

The automail requirements are a complete arm without a wearer, ivory/graphite/
gold broad appearance, meaningful rigid pivots, a removable service cover,
five separate digit chains, a 3 mm cover offset with protected neighbors, and
limited elbow/wrist/digit pose checks. Dynamic hydraulics, physical loads,
neural control, skinning and a target game engine are outside this exercise.

All authors inherit the same host model configuration; provider/model IDs,
token counts and prices are unavailable. A roughly 30-minute working allowance
guides scope but is not an instrumented compute cap. Starts, ends and overruns
are reported rather than normalized away. Parallel render contention and
staggered scheduling prevent a controlled speed ranking. There is one author
per automail condition; any preference is exploratory, not statistical evidence
of skill superiority.

## Evidence and comparison

Preserve first complete candidates, focused corrections, failures and the
selected neutral baseline. Retain original source bytes and record all file
identities. Use actual Blender renders with fixed camera/light records. Source
panel associations remain unregistered: the cameras have not been calibrated
against the design sheet.

For cross-condition inspection, realize curves and text only in separate audited
observation copies and check that source native bytes stay unchanged. Explicitly
record excluded studio objects outside each declared asset root. Render
the three neutral automail candidates under one external specification. Do not
compare different authors' lighting as if it were a geometry-only difference.

An independent reviewer receives the full source sheets and anonymous actual
views, without author conditions, intended fixes or prior conclusions. Review
whole proportions and readable connections before local detail. Keep the raw
verdict even when it favors a control or rejects every candidate. Pose output
and written technical checks are reviewed separately from source resemblance.

Record geometry, transforms and materials for protected parts; counts alone
are insufficient. State whether restoration proves exact file/input bytes or
only reopened geometric state. Check required hierarchy in an independently
reimported GLB. A few successful pose samples cannot establish full motion
clearance, mechanical feasibility or complete animation support.

The source manifests and task scripts are in `examples/uniform-jacket/` and
`examples/automail-arm/`. The prior original three-condition garment result
remains in `../uniform-jacket/`; it is not replaced by this informed continuation.
