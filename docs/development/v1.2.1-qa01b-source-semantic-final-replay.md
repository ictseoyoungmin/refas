# v1.2.1 QA-01b — current-GLB source relation receipt, fail closed

Parent: [QA-01 #265](https://github.com/ictseoyoungmin/refas/issues/265), [QA-03 #271](https://github.com/ictseoyoungmin/refas/issues/271), P0 [#272](https://github.com/ictseoyoungmin/refas/issues/272). **Bounded release-blocker slice; this is not complete QA-01/QA-03 or a v1.2.1 release.**

## Regression threat

The existing read-only `verifySourceBoundObject(root, assetFile)` sources `relational-evidence` from three SHA-matching artifact refs in the *current head* and the broad `trustedCertified` boolean. It may elevate these relation claims to `PASS` without independently re-running original-source part semantics against the **current supplied candidate GLB bytes**. Another verifier's artifact SHA, claim audit or GLB schema success is **not evidence** that front and rear basket semantic roles, visible structure contacts or actual physical part sizes match the original photo.

## New mandatory negative gate

`source-semantic-current-glb` is always a **required check** in the public `source-bound-object` QA report. Installed verifier builds exact accepted checkpoint ancestry from the current head; requires a current original `visual-observation` checkpoint with one `reference-geometry`, accepted `shape-reconstruction` with one original `realized-projection` and one shape-stage GLB. All artifact paths must resolve **within project root**, with exact size + SHA match. The original registered projection is re-verified against actual shape-stage GLB bytes and source SHA before trusting its frozen camera or node bindings. The current *user requested QA candidate GLB bytes* are projected anew with those signed, source-bound bindings. No worker-authored `PASS`, fabricated camera, arbitrary file or earlier GLB provenance can authorize a replay.

Run QA-03a (source-visible identity role pairs, independent physical GLB mesh projected area/order) and QA-03b1 (original source-explicit structural joint contacts vs actual projected distinct mesh hull gap) on the supplied current candidate. A measured source-observed GLB physical contradiction yields `FAIL`. Missing, hidden, inconsistent, non-projectable or **merely source-attested but not independently human/reviewer-verified photo semantics** remain `INSUFFICIENT`. No identity part/structure observation is `NOT_RUN` or `INSUFFICIENT`, **never NOT_APPLICABLE => PASS**. Source and GLB hashes stay recorded in the check's evidence. A valid GLB without checkpoint history returns `NOT_RUN` for this check while `glb-integrity` may be `PASS`.

The previous `relational-evidence` check keeps its exact artifact/current certification validation, but any potential `PASS` is constrained: **current source semantic mismatch => FAIL; no mismatch but missing independent original-source role authority => INSUFFICIENT**. The validator does not demote an existing `NOT_RUN`/explicit `FAIL` or misrepresent a photograph as machine-classified. Both checks appear in `blockingCheckIds` when not PASS, so public `refas verify --profile source-bound-object` remains BLOCKED (exit code 2).

## Falsification

- Real `partsToGlb` candidate front-large/rear-small part meshes with source visible original roles: source candidate relation `NO_DETECTED_CONTRADICTION` yields final `INSUFFICIENT` because independent source semantic attestation is absent.
- Swap **physical current candidate mesh sizes** after an unchanged valid original shape proof => `FAIL` with actual GLB role area reversal.
- Inject a worker-claimed checksum/audit relational `PASS`: gate forces `INSUFFICIENT` or `FAIL`. Missing report remains `NOT_RUN`.
- Alter shape GLB bytes behind original proof, substitute source SHA or scope => rejects exact proof. Non-GLB current candidate cannot prove anything; remain `INSUFFICIENT`.
- Public QA on valid GLB but zero checkpoint ancestry explicitly adds mandatory `source-semantic-current-glb NOT_RUN` and BLOCKED.
- Node20/22/24 regression, Node24 installed Fresh-worker+VC08, immutable exact-head review and postmerge CI required before scoped CLOSED.

## Residual gate ownership

**Independent source meaning is still NOT established.** This patch does not invent an image semantic classifier, human-source signoff, source inventory for missing diamonds/struts, actual 3D mechanics or multiview proof. Thus clean source-bound objects remain *unqualified for source-fidelity PASS* under this restrictive new check until a separately independently verified original source evidence receipt is implemented. This intentionally prioritizes the release's "no false positive" contract over issuing self-certified success. Next #271 requires trusted original source semantic role/reviewer provenance and topology inventory, while #265 requires unified Host/handoff certification admission. At least one permission-safe real-photo external fresh-worker positive+negative and exact full Deep QA are required for v1.2.1. No change to stable `main`.
