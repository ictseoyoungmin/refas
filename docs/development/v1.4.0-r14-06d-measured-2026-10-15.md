## Implementation and private source authority

New opt-in `benchmark_pbr_v2_full.py` loads and SHA-binds the **actual
original GLB and frame bytes** once in a single Python process, then
records the first invocation (which may include cold JIT), three warm
repeats and two alternate tile/worker settings for each resolution.
It explicitly compares every pass's **raw RGB and encoded PNG SHA** plus
exact float64 depth/int64 original winner/float64 original barycentric
buffers across all repetitions and configurations, and fails closed on
any mismatch. GLB decoding, PNG encoding, SHA hashing and report I/O
are deliberately **outside** the measured render wall timer.
It stores CPU/Numba/NumPy versions, phase timings, coverage, source
triangle counts, input/frame digests and cumulative `VmRSS`/`VmHWM`
read from the process. Results are atomically published and refuse
an existing output folder.

The **unchanged user source GLB**:
`monster_bed_v4.glb` (26,129,684 bytes), SHA-256
`30f8e135a34470366780b9b600040dff823171dfe857e7e4ab681c520a95f8d7`.
**901,664 indexed source triangles** / **40 primitives** / fur
**512,000** triangles, with original linear RGB COLOR_0 data.
Not committed to GitHub, not decimated, no sparse proxy. Frame is
the same explicitly **non-source-photo-registered** provisional
Hero; frame-file SHA `76074dec7ae1dd8accc00453426f13d8070c45dc0f696dfe01ed5739b2e2a5a1`.
Rendering here neither authenticates the camera registrationDigest nor
compares any source photograph.

Hardware/profile: AMD EPYC **9V74 80-Core Processor**, Python 3.13.5,
NumPy 2.3.5, Numba 0.65.1, Linux 6.18.44, reported `os.cpu_count=5`,
Numba maximum threads **4**, OpenBLAS 1, baseline tile32/4 threads,
1024MiB renderer preflight. This is **not** a production SLA and

## Separate **synthetic** 1024px indexed-texture stress

New deterministic `create_pbr_v2_texture_benchmark_fixture.py`
creates a genuine indexed **120-triangle** glTF 2.0 GLB with a
**1024×1024 embedded RGBA PNG** (17,656 compressed bytes in this
repeated-pattern fixture), original vertex TEXCOORD_0 with high UV
frequencies, `LINEAR_MIPMAP_LINEAR` (9987), REPEAT × MIRRORED_REPEAT.
Fixture source SHA:
`9d5b9532359a4949390f50e866a5a95259176997b2866b048c304b8b70e93856`.
Seed **137**. This fixture is generated, **NOT the Monster Bed** and not
source-photo evidence. It drives actual analytic LOD and trilinear mip
filtering in all visible shaded pixels. The same host and process
method were used, but a separate Python benchmark process; do
**not** compare its memory/throughput directly with the dense real GLB.

The generated fixture's high-frequency texels deliberately
**minify to nearly uniform colors at 384px**; this is a test of
filtering/LOD convergence, not a visual-quality demo. Source
texture/NPOT/mip/UV derivative correctness was separately tested with
independent analytic pixel oracles in R14-06C3. Process cumulative
VmHWM at this fixture's end: **346,092 KiB (~338 MiB)**.

## Explicit scope of the work, tests, and limitations

- `tests/test_render_pbr_v2_full_benchmark.py` runs a small **real
  indexed GLB binary** with a 256px PNG and mip filter, tests
  source/frame digest binding, repeat/alternate full pixel/visibility
  SHA parity, preview-only report, immutable source and refusal to
  overwrite or accept a wrong user-provided source SHA.
- The private user Monster Bed GLB is **not added to a GitHub workflow**.
  The full 901k/1024px results were measured locally with source SHA
  and platform identity; repeated fixed-host PR/merge CI runs use only
  small generated sources.
- The worker provides *direct three-light*, limited metallic/roughness
  **material previews**, not a full glTF PBR result with IBL,
  area lighting, shadows, transparency, normal maps, all glTF
  extensions or an independent GPU correctness oracle.
- Required for R14-06E/F: choose and test an **actually installed**
  independent external PBR renderer, match lighting/camera/material
  profiles, replay source proof and compare with genuine photo-registered
  canonical views. Issue #364 remains open; no visual resemblance
  or material-fidelity certificate is implied.

## Reproduction

```bash
NUMBA_NUM_THREADS=4 OPENBLAS_NUM_THREADS=1 python3 \
  skills/refas/scripts/benchmark_pbr_v2_full.py \
  --glb path/to/monster_bed_v4.glb \
  --frame path/to/provisional-diagnostic.frame.json \
  --expected-glb-sha 30f8e135a34470366780b9b600040dff823171dfe857e7e4ab681c520a95f8d7 \
  --out temp/r14-06d-monster --sizes 160,384 --threads 4 --tile 32 \
  --repeats 3 --alt 1:16,4:64 --max-working-mb 1024
```

Reproducing **numeric time medians** requires the same hardware and
runtime; reproducing PNG and winner/depth SHA requires the same
source bytes, provisional frame, worker versions and deterministic
sampling. PNG and report/source digests are checked separately.
