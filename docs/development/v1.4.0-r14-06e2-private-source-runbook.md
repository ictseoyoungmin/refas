## Verified boundary / mandatory checks

The E2 adapter independently preflights source indexed triangle counts,
source primitive count and true COLOR_0 triangle inventory.
The separately launched native Blender glTF importer/renderer then
checks **each imported color-bearing object's USED material slots**
(not just one unrelated global material node), all actually imported
indexed faces, original COLOR_0 shader linkage and source SHA.
Blender's own Cycles worker reports import/render wall time and
Linux `/proc/self/status` **VmHWM (process cumulative)**. Its resource
preflight is advisory and NOT an OS-level memory cap.

The E2 verifier validates real imported count against **901,664**
source triangles, **40** original source primitives, source and frame
SHA, at least **512,000 original color-bearing source triangles**,
actual colored imported face count, material graph links, nonconstant
160/384px PNGs, complete PNG bytes SHA, same Blender worker/version,
and source immutability. It fail-closes on any mismatch. It never
asserts CPU-to-Cycles RGB SHA equivalence because the lighting,
BRDF, tonemapping and world backgrounds differ.

Every accepted report is still
`claimScope: external-pbr-preview-only`,
`certificationEligible: false`,
`cameraAuthority: UNREGISTERED-DIAGNOSTIC`,
`crossRendererEquivalence: NOT_ESTABLISHED`,
`referencePhotoResemblance: NOT_EVALUATED`.
No output generated by Blender is allowed to certify itself.
