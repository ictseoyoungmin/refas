# R14-05B — Subpixel microtriangle correctness

Status: IMPLEMENTATION CANDIDATE — diagnostic raster semantics only; pending CI review. Does not close the high-density R14-05 performance gate.

## Correctness defect and remedy

Previously the R14-03/R14-05A tiled diagnostic worker discarded a triangle
whenever the absolute 2D projected triangle area was < `1e-12`, even if
that *nonzero* area still enclosed an exact raster sample location. In the
Normal pass an additional `length(world_cross) <= 1e-20` threshold could
discard the same valid triangle. Thus Normal and Object-ID could fail to
describe actual scene geometry, particularly for thin hair strands.

The new **RefAs Tiled CPU/0.2.0-microtriangle** profile rejects only exactly
zero or nonfinite area/normal length. It still requires the original Numba
raster top-left edge tests and exact depth/tie ordering. A positive-area
triangle with no covered raster sample remains invisible under the current
single-sample, no-antialias policy; that is different from rejecting geometry.

Its shared three-pass companion uses **RefAs Visibility
CPU/0.2.0-microtriangle** and a new cache key. The internal JS trusted
backend registry now requires `tiled-cpu.algorithmVersion = 2`, and exact
renderer version `0.2.0-microtriangle`; old algorithmVersion `1` jobs are
rejected rather than silently accepted under a different raster rule. Cache keys still include
the source file/frame/camera/runtime/renderer script digests; pre-fix
diagnostic visibility buffers cannot be replayed across this profile change.
The new profile is **not** equivalent to v1.3.0 registered exact PNG replay,
the canonical eight-view PBR renderer, an anti-aliasing or coverage
integration algorithm, or a source-resemblance certificate.

## Focused adversarial tests

`tests/test_render_cpu_microtriangles.py` includes:

- Positive finite screen triangles with area less than `1e-12` that
  genuinely cover one pixel center. An ultra-thin test also has a nonzero
  world normal length below the former absolute `1e-20` cutoff.
- Normal/Object-ID matching depth and winner buffers; 16/32/64 tiles and
  1/2 workers (when available) give exact image/depth/winner equality.
- Positive-area subpixel triangles that cover **no** sample location remain
  invisible. Exact collinear/repeated-index degeneracy remains excluded.
- Shared three-pass visibility cache cold/hit retains the same single
  visible microtriangle pixels; tamper and invalidation tests from R14-04
  continue to be required.

This correctness pass does **not** claim all thin strands become visible at
small resolutions. Any triangle that misses every point sample must still
be absent; MSAA/analytic pixel coverage is a separate, versioned feature
requiring new quality and performance validation.

## Remaining R14-05 gate

Run documented, true nondegenerate 10k/100k/500k/1M workloads and provided
Monster Bed GLB where available; measure hardware, wall/RSS, JIT cold/warm
time, bin occupancy and raster stages. Validate clipping and overlap on
the native GLB geometry and tile/worker parity. High-density production
claim and any canonical-view certification remain blocked until measured.
