# RefAs 1.4.0 — compiled CPU raster kernel specification (design)

Status: DESIGN. This is a proposed implementation contract, not a claim of current behavior. Select the shipping language and precise numerical raster profile after the baseline benchmark. Preserve all v1.3.0 legacy byte-replay semantics.

## Vertical-slice ABI

The first accelerated profile covers an immutable indexed triangular mesh, one canonical perspective camera, opaque rasterization, a single registered hero image, and `normal`/`object-id` passes. Do **not** merge with canonical 8-view admission until it has passed the full trust contract.

A new kernel consumes arrays, not Python triangle objects:

| Buffer | Proposed representation | Ownership |
|---|---|---|
| `position_xyz` | contiguous `float64[N,3]` camera/world staging | immutable |
| `normal_xyz` | contiguous `float32[N,3]` or `float64`, declared normalization | immutable |
| `uv` | contiguous `float32[N,2]` where present | immutable |
| `indices` | `uint32[T,3]` / `uint64` if overflow checked | immutable |
| `primitive_id` | stable integer per primitive | immutable |
| `source_triangle_id` | original global ordinal preserved after clipping | immutable |
| `raster_triangle_id` | stable split ordinal for near-plane clipped polygons | immutable |
| `tile_offsets` | `uint64[numTiles+1]`, prefix sums | immutable |
| `tile_triangle_ids` | bounded packed ordinals | immutable |
| `depth`, `winner`, `barycentric` | one output per pixel, owned by a single tile worker | mutable only within owned tile |

Data layout is an explicit benchmark decision: SIMD-friendly SoA may store separate x/y/z arrays, while exported/diagnostic interfaces can remain AoS. Conversion overhead must appear in timing. A possible Rust/C ABI is an internal optional worker, not a public promise or a new required package dependency.

## Raster semantics and deterministic tie rule

1. Validate every finite input, index and accessor range; reject unsupported draw modes/material alpha states before any certifying output.
2. Transform indexed vertices once into camera homogeneous space and clip triangles against near plane. Clipping that splits an input triangle into two outputs preserves its stable source ordinal and assigns deterministic split ordinals. Apply accurate side-frustum clipping or screen-clamped conservative bounds; do not silently discard a partly visible triangle.
3. Project to declared resolution with one versioned pixel-center convention and one versioned top-left edge inclusion policy. Choose float64 or documented fixed-point edge math with explicit overflow tests. Record subpixel precision and depth representation in backend identity.
4. Reject only provably degenerate triangles under that profile, including correctly detected zero-area triangles. Dense subpixel geometry must not be treated as zero-area solely for speed.
5. Resolve depth ties with a strict total order, e.g. closer signed depth first, then lower `(primitive_id, source_triangle_id, split_ordinal)`. Do not let thread completion order decide the winner. Match the tie policy in the goldens.
6. Perspective-correct UV, normal and position interpolation uses the same accepted winner barycentric/depth record; normal orientation under negative determinant transforms has a declared policy.
7. Tile worker writes only its own pixel and coverage region. No globally shared destination writes, no non-deterministic atomic blending. Ordered alpha/transparency is a separate later feature with explicit gate, not a silent opaque approximation.

## Two-pass tile binning

```text
setup triangles in stable global ordinal order
for each triangle:
    bound it to clipped framebuffer rectangle
    determine overlapping tile range
    increment per-tile counts with overflow checks

tile_offsets = exclusive_prefix_sum(tile_counts)
if tile_offsets[-1] > maxBinEntries / memory budget: BLOCKED_RESOURCE

allocate packed tile_triangle_ids[tile_offsets[-1]]
write cursor[tile] = tile_offsets[tile]
for triangle in original stable order:
    for overlapping tile in canonical scanline tile order:
        slot = cursor[tile]++
        tile_triangle_ids[slot] = triangle.ordinal

parallel_for tile in 0..numTiles-1:
    rasterize tile_triangle_ids[tile_offsets[tile]:tile_offsets[tile+1]]
    store depth / winner / coverage in disjoint tile area
```

A GPU-like tile list is not equivalent to the v1.3.0 loop's per-triangle scratch tiling. This method pays a one-time binning cost and enables bounded reuse, locality and parallel work.

A naïve binning design can explode on very large triangles. Enforce checked `uint64` multiplication/addition, an explicit membership budget, allocation preflight and a documented oversized-triangle path. No silently dropped triangles. Per-worker scratch plus tile lists must fit the declared `workingMiB` with headroom for decoded GLB/textures and Python/worker overhead.

## Performance and resource metrics

The trusted benchmark runner needs the following counters for every backend/version/size/view:

- GLB byte size, decoded vertex/index/texture footprint, total/valid/clipped/frustum-rejected triangles;
- number of bin entries, occupied tiles, largest tile queue, submitted and depth-visible fragments;
- decode, world/camera transform, clipping/setup, binning, raster/depth, shading, PNG encode and final publish durations;
- wall time, CPU time, peak RSS, thread count, vector instruction profile and cache cold/warm flag;
- input GLB/frame SHA, actual output PNG SHA, runtime/backend/algorithm and machine model;
- typed `COMPLETE`, `BLOCKED_RESOURCE`, `BLOCKED_TIMEOUT`, `BLOCKED_UNSUPPORTED`, `FAILED_ASSET` or `FAILED_BACKEND` without converting timeout to geometry failure.

Report counts separately from render success. A scene with a million zero-area triangles is not evidence for performance on a million actual triangle surfaces.

## Test plan for the first compiled slice

**Correctness:** near plane, offscreen clipping, shared edge and top-left fill, exact depth tie, negative scale, perspective interpolation, skinny/subpixel triangle, repeated instance identities, >2^32 boundary checks where relevant.

**Determinism:** repeat identical job with 1, 2, 4, 8 threads and 16/32/64 tiles, compare per-backend pixel hashes; compare numerical policy across CPUs that the profile actually declares supported. Same SHA across unrelated renderer versions is not expected.

**Stress:** 10k/100k/500k/1M real nondegenerate triangles with randomized-but-seeded overlapping strand bundles, tiny visible fragments and large triangles; record throughput/RSS; stage and timeout fault injection; do not put all stress variants into every PR CI run.

**Integration:** preserve v1.3.0 `render_glb.py` and its hero replay on old PNGs; do not authorize accelerated output using that pinned identity. Distinct optimized backend certification requires its own independently validated replay adapter.

## Implementation decision gate

Start with R14-00 baseline and one R14-02 opaque hero slice before inventing a general renderer abstraction in code. Prototype in Numba only where available; benchmark native options and distribution impacts before picking an implementation. If the added native dependency is not portable, keep a runnable Python fallback and explicitly record backend selection. A performance regression, invalid pixel parity or failed legacy replay blocks promotion, not necessarily all development work.
