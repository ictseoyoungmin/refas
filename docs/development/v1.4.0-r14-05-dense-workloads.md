# R14-05A — Dense raster bounds and measurable Hero CPU workload

Status: IMPLEMENTED candidate on the **R14-05 development PR**, pending measured
500k/1M hardware acceptance. This is the first narrow performance slice, not
closure of R14-05 or a certification upgrade.

## Implementation and correctness contract

The diagnostic Numba-tiled CPU worker formerly tested *every pixel in the
entire tile* for every binned triangle, including subpixel fur triangles.
The R14-05A path intersects the conservative projected triangle bounding
rectangle with that tile before the exact edge/depth/top-left tests. It does
**not** change projection, near-plane clipping, backface/degeneracy handling,
depth interpolation, winner ordering, coverage policy or color calculation.
No triangle/vertex decimation, proxy, LOD or source-certifying fallback exists.

Two measured counters report the difference in work rather than inventing a
speedup: `tileWidePixelTests` = candidates under the previous whole-tile loop,
and `candidatePixelTests` = candidates under this bounding-box iteration.
These count potential edge-test locations; they are not covered fragments or
actual drawn pixels. The existing `depthUpdates`, `coveredPixels`, tile bin
and stage timings remain separately recorded.

`tests/test_render_cpu_dense_bounds.py` reproduces the former full-tile
edge/depth loop in standalone Python as an oracle, comparing RGB, exact depth
and winners across tile sizes, equal-depth overlap, a large partial triangle
and a subpixel triangle. Dense 12k positive-area fur checks require fewer
candidate locations. Existing R14-02/03/04 tests continue to cover clipping,
cache invalidation and pixel parity. No v1.3.0 renderer or public installed
skill API was modified.

## Repeatable dense benchmark

Optional NumPy/Numba tooling: install `numba==0.65.1` in the performance
environment (ordinary RefAs users have **no** additional required dependency).

```bash
# Fast diagnostic proof, no certification:
python3 skills/refas/scripts/benchmark_render_cpu_dense.py \
  --case strands --triangles 10000 --size 96 --tile-size 32 \
  --threads 1 --repeats 3 --out temp/r14-05a-10k.json

# Large stress runs only on a controlled CPU runner with declared memory:
python3 skills/refas/scripts/benchmark_render_cpu_dense.py \
  --case strands --triangles 1000000 --size 160 --tile-size 32 \
  --threads 4 --max-working-mb 1024 --timeout-seconds 600 \
  --repeats 3 --save-fixture temp/r14-05a-1m-source \
  --out temp/r14-05a-1m.json

# Existing real model: never substitute the synthetic asset for source QA:
python3 skills/refas/scripts/benchmark_render_cpu_dense.py \
  --glb temp/monster_bed.glb --frame temp/monster_bed-frame.json \
  --size 160 --tile-size 32 --threads 4 --max-working-mb 1024 \
  --timeout-seconds 600 --repeats 3 --out temp/monster-bed-dense.json
```

The runner preserves input GLB/frame hashes, optionally retains generated
positive-area geometry, produces three real diagnostic pass PNGs through
`render_cpu_visibility.py`, checks diagnostic report source identity, captures
per-run kernel counters/PNG digests/wall time, and samples peak subprocess RSS
from Linux `/proc` when available. It emits explicit blocked/failed outcomes
instead of fake throughput. Every repeat is an independent fresh process, so
**each repeat includes cold Numba JIT**: no warm-JIT speedups may be inferred.
The cache is disabled. No performance claim or 10-minute SLA can be made
until these pinned measurements actually run.

The original R14-00 `benchmark_render_cpu.py` is the **separate legacy
reference**, but the legacy Portable renderer and optimized diagnostic workers
currently cover different passes. Raw elapsed time ratios are not an
equal-quality/PBR renderer speedup.

## Remaining R14-05 closure work

1. Measure 10k/100k/500k/1M nondegenerate triangles on the **same documented
   CPU/GLB/camera/resolution** with at least three runs; compare full-kernel,
   parse and RSS costs. Include real Monster Bed GLB when supplied.
2. Add correctness stress for ultra-subpixel and extreme near-clip geometry;
   investigate the existing `abs(projected_area)<1e-12` setup policy without
   silently widening what counts as degenerate or breaking pixel identity.
3. Profile setup/camera transforms and the current worst-case 2x triangle
   allocation. Optimize only after locating the measured peak, then rerun goldens.
4. Compare 1/2/4/8 threads and 16/32/64 tiles on the same fixture; characterize
   peak RSS, scheduler and cache effects. Keep large sweeps **manual/opt-in**.
5. Close R14-05 only after documented source-asset Hero and canonical-view
   acceptance or typed renderer limitations, without granting diagnostic cache
   any v1.3.0 certification authority.
