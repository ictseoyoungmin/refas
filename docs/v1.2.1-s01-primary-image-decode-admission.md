# v1.2.1 S01a — Primary source image decode admission

Parent: [P0 #272](https://github.com/ictseoyoungmin/refas/issues/272).
Integration base: `develop/v1.2.1@ac929dc6c178efb9f59b22e6b45355b05b1d763a`.
This is a bounded **source-manifest CLI input-hardening sub-slice**, not a full S01 closure, photo-vs-render comparison, new top-level capability or source-fidelity certificate.

## Defect and enforcement

The image-manifest generator previously used `Image.verify()` after reading size metadata. That does not guarantee that all image pixels can actually be decoded before the manifest reports success. The raw original reference may also carry EXIF mirror/rotation; RefAs v1 source observation coordinates reference the manifest's encoded width and height, so silently accepting rotated display coordinates would make a source-space landmark refer to the wrong frame.

The canonical `refas source-manifest` helper now:
- fully loads the original raster through Pillow before creating the manifest;
- rejects corrupt/truncated raster payloads, multi-frame source images and excessively large (> 40 million) decoded pixel dimensions;
- accepts only absent/canonical EXIF orientation (1); other mirror/rotation values fail with an actionable error instead of silently changing source coordinates;
- leaves the original bytes untouched, retains the existing `refas.source-manifest/v1` fields, and binds its original SHA-256/byte count as before.

Positive PNG and JPEG still photos pass. Deliberate EXIF orientation 6, truncated JPEG and animated GIF all fail without writing a manifest. The new Node regression invokes the same distributable Python helper using actual generated image bytes.

## Boundaries not proven by this change

This verifier runs at the **manifest generation CLI** boundary. A worker can still provide a hand-written source manifest through other APIs; the installed checkpoint/host paths do **not yet independently replay image decoding or trusted pixel-space source observations**. Thus **S01 remains OPEN**, #272 remains OPEN/ACTIVE, and no Reference Fidelity PASS is authorized. Next S01 work must bind original pixel-frame decode and observation/provenance to trusted source-intake/current source registration; S02 must independently compare actual original pixels to rendered candidate masks/edges/occlusions.

The orientation policy is intentionally conservative until the source coordinate transform contract explicitly supports EXIF oriented photos and preserves both original-source SHA and source-view coordinate mapping. For now, preserve the original file and normalize a separate explicit source copy, rather than silently rotating original bytes during manifest generation. Never claim that image decoding proves a correct contour, camera hypothesis or 3D likeness.
