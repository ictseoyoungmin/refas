# P0 #272 — Source-space macro observation admission (first bounded slice)

This document tracks the **first** runtime enforcement slice of [P0 #272](https://github.com/ictseoyoungmin/refas/issues/272) on `develop/v1.2.1`. It is **not** a full camera registration, projected landmark, photo likeness or Game Ready claim.

## Existing authoritative operation

`commitCheckpoint` already calls the installed `checkpoint-store.mjs` early resemblance admission when a real, non-fixture source-bound worker attempts `surface-topology` or a later capability. That path validates source/candidate-linked neutral-clay renders, macro perceptual signatures, candidate GLB and visual hierarchy, and the protected spatial role / volume barrier. A worker could formerly omit the upstream `reference-geometry` entirely and still satisfy the early resemblance check.

The new runtime admission requires exactly one **upstream `visual-observation` checkpoint** with an actual `refas.reference-geometry/v1` artifact, not a claim in the downstream worker's prose. It checks:

1. Actual project-contained artifact bytes, byte size and SHA-256, using the existing `readCheckpointJsonArtifact` code path.
2. Canonical `validateReferenceGeometry` result, the exact current primary source SHA and spatial scope.
3. At least one source-visible (not inferred-only) **macro** primitive with a raw-primary-source path citation, and a raw-primary-source citation on the observation attestation.
4. Existing neutral-clay/early resemblance / spatial role / volume checks still run and must independently pass.

A canonical but **empty** observation file is insufficient, and a swapped source SHA or stale/re-signed evidence file fails. This check does not assume user-authored observation metadata is verified source visual truth; an independent reviewer or trusted source interpretation is still necessary for full #272 and QA-03 #271. A valid `reference-geometry` alone does not certify camera choice, depth, occlusion or reference likeness.

## Regressions and next gates

Tests use an actual source-bound non-fixture checkpoint and current GLB. Positive: source-cited macro anchor plus whole contour, current neutral-clay `PROCEED`, downstream checkpoint admitted when existing barriers pass. Negatives: omission, empty source geometry, canonical changed source digest, source geometry bytes modified after checkpoint. Previously implemented HOLD/REWORK and volume-collapse negatives remain valid.

**Still mandatory to close #272:** trustworthy camera-hypothesis authority and candidate registration, current GLB reprojection of source-observed silhouette/head/face/shoulder/torso landmarks and occlusion/negative spaces; uncertain single image -> review required, contradictory macro -> typed upstream reopen and downstream invalidation. Do not infer a `PASS` from worker-written 2D observations, `projection-fit` digest alone, single-view IoU, camera fit alone, or neutral-clay image existence. Independent source-to-asset semantic checks #271 and overall strict QA #265 remain unclosed. Stable `main` v1.2.0 unchanged.
