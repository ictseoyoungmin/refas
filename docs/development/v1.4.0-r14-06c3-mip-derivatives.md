# R14-06C3 — analytic UV derivatives, deterministic mip filtering and bounded texture decoding

Status: **IMPLEMENTATION CANDIDATE / MEASURED ACCEPTANCE PENDING**. This
material-preview-only slice does not upgrade the independent PBR v1 renderer,
trusted evaluator, PBR report schema, R04 Neutral-Clay replay or public main.

## What is actually implemented

- **Per-winner original-triangle UV gradients.** R14-06B provides original
  GLB triangle IDs, per-pixel original barycentric weights, exact ray depth
  and camera-space original vertex positions. For a camera ray `r(x,y)`,
  source camera vertices form `M=[A B C]`, with
  `q=M^-1 r`, `UV=q·UV_vertices / sum(q)`. Analytic derivatives of
  the rational mapping use pixel ray `dr/dx` and `dr/dy` rather than
  sampling neighboring pixels with potentially different occluders.
  Near-clip provenance is preserved; singular geometry **fails closed**.
- Magnification uses declared glTF `magFilter`; minification uses
  declared `minFilter`. Supports `NEAREST`, `LINEAR`,
  `NEAREST_MIPMAP_NEAREST`, `LINEAR_MIPMAP_NEAREST`,
  `NEAREST_MIPMAP_LINEAR`, `LINEAR_MIPMAP_LINEAR`.
  Footprint `rho=max(|dUV/dx*(width,height)|,|dUV/dy*(width,height)|)`
  determines `LOD=log2(rho)`. Level selection is nearest or adjacent
  trilinear, with independent texel nearest/linear filtering as declared.
- **Mip construction happens in linear RGB**, after IEC piecewise sRGB
  decoding of embedded PNG bytes. Adjacent 2×2 linear texels are box
  averaged; NPOT edges replicate the last texel. This edge handling and
  level generation are a **pinned v2 preview policy** rather than a
  glTF-specified universal image-authoring mip reference. glTF permits
  implementation-chosen defaults when sampler filters are omitted; the
  preview pins LINEAR/level-0 defaults instead of guessing from results.
- Shares decoded/mip arrays across repeated primitive references to the
  same image/filter choice. Texture bounds: 2,097,152 texels per image,
  4,194,304 total decoded image pixels, 16 MiB compressed PNG payload
  per image, and conservative renderer+visibility+mips preflight
  `384 MiB + original 2-fan geometry buffers + viewport + 96B/image pixel`.
  **This is NOT an OS memory cgroup limit.** PNG header dimensions and
  encoded payload limits are checked **before** the v2 loader decodes RGBA;
  the v1 GLB loader's default invocation remains unchanged.
- Version identity: `RefAs PBR v2 Opaque Preview/0.3.0-analytic-mips`.
  The report remains explicitly **`material-preview-only` /
  `certificationEligible=false`**. Image, source GLB, camera frame and
  geometry buffer digests remain bound to the output. No new PBR
  certification or similarity statement is authorized.

## Acceptance gates

`tests/test_render_pbr_v2_mip.py` uses an independent **3D
ray/triangle plane-intersection finite-difference oracle** to check the
analytic UV derivatives, a different-color 4×4 alternating mip sample
at known LOD 0/0.5/1, four enum mode contracts, mag/min handoff,
NPOT 3×3 edge-averaged mip colors, singular triangle refusal and
source-triangle-specific computation across occlusion. Original
`test_render_pbr_v2_texture.py` remains and now verifies mip filter
enums **only when screen derivatives are available**.

## Explicit boundaries / next

This slice does NOT implement alpha MASK/BLEND, IBL, area lights, shadows,
normal maps, emissive/misc. material extensions, anisotropic filtering,
texture transform or a general glTF sampler derivative reference for
all transform modes. Full PBR and trustworthy photo resemblance remain
unproven until separately installed/checked independent backend and
source-registered 8-view evidence in R14-06E/F. Issue #364 remains open.
