## R14-06E2 implementation

`skills/refas/scripts/qa_external_blender_private.py` executes the
reviewed **E1 external Blender adapter** on an installed Blender
binary on the **same host as the privately-held original GLB**.
It NEVER makes a network request or uploads a source file.

- Requires explicit `--source-kind PRIVATE_ORIGINAL` versus
  `SYNTHETIC_TEST`. Default source/diagnostic frame SHA and triangle
  expectations are the actual user's Monster Bed, NOT inferred
  from a generated proxy. It checks source/file hash before and after
  all renders.
- Executes 160/384px by default in the same private environment.
  The Blender glTF importer must actually produce the full expected
  source triangle count. A real imported mesh `COLOR_0` color layer
  must be linked to a shader material node, not merely declared in
  a source manifest.
- Reads original-source-bound E1 Blender version, worker SHA,
  camera SHA, actual PNG SHA and import/render timings. Reports
  `refas.external-blender-private-fullsource/v1` with
  `certificationEligible=false`, `external-pbr-preview-only`,
  `crossRendererEquivalence=NOT_ESTABLISHED` and
  `photoResemblance=NOT_EVALUATED`. No direct self-certification.
- Monitors Linux Blender process-tree aggregate VmRSS roughly every
  150ms, terminates over-budget/time-out processes, reports
  maximum **sampled** RSS. This is explicitly *NOT* a hard
  kernel cgroup peak/memory limit. Do not claim hard OOM prevention.
- Publishes source-SHA-bound output only if **all requested views
  succeed** and refuses stale output directories. The preview report
  does **not** include the original private GLB itself.
