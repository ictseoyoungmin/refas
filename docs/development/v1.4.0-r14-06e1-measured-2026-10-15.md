## Stronger counterfactual instead of self-certifying a bound node

A second **synthetic control** GLB contained the *identical original*
indexed geometry, embedded PNG, TEXCOORD_0, and materials; only the
`COLOR_0` attribute declaration was omitted in a separately
sha-bound **test fixture**. This does NOT modify or decimate
the user Monster Bed. Control fixture SHA:
`48080d48f184252f744b0d77610adfe9dd2a57c254b8744f10bd8001dc920134`.
Its independently executed Blender Cycles output PNG SHA
`9b610b01b5fbbb031437a3578f9cc2428c9c5a0cd265b6f487fa3e3eebfc3ea6`.

Against the COLOR_0 source render, **12,588 of 25,600 pixel positions
changed** by more than two in at least one RGB channel, global mean
absolute RGB difference **12.427865**. The source/control
source-triangle inventory remained **120/120 identical**, so this
establishes a **causal real shaded-pixel effect** of the original
COLOR_0 input under the installed independent engine. It does **not**
prove glTF material equations universally match the CPU preview or
that these renders resemble any external source photograph.

### Earlier failed protection tests and resolution

One deliberately strict Blender 4.0.2 material binding check
initially failed (Actions #38741477217 and #38741793971).
It required the shader node to explicitly name the `Col` attribute,
but the actual linked Blender native `VERTEX_COLOR` node relies
on the active render color layer and has an empty `layer_name`.
The code was corrected to accept a **linked native vertex-color
node tied to the unique imported active layer**; a separate pixel
A/B counterfactual was retained as a stronger proof than node names.
The final successful source and output hashes are those above.
This is a measured implementation correction, not a claim that
all possible Blender versions share the same node graph.
