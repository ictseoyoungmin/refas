# RefAs 1.2.1 QA-03a — source-visible identity part size/order vs actual GLB

Parent [#271](https://github.com/ictseoyoungmin/refas/issues/271), P0 [#272](https://github.com/ictseoyoungmin/refas/issues/272). This is a bounded development **contradiction screen**, not QA-03 completion and NOT reference identity certification.

## Observable failure

A source-annotated bicycle clearly has a larger front basket and smaller rear basket, separated in the original photo. An agent can replace the front/rear GLB mesh geometry (or invert spatial positions) while keeping valid meshes, the same metadata labels, syntactically valid relation reports and a rendered whole silhouette. Single-view whole-object IoU or the macro-only S03a cannot detect every identity-part substitution.

## Gate

The existing `refas.reference-geometry/v1` is saved at **visual-observation**, before candidate construction, and digest-bound to original source SHA. For each visible `importance:'identity'` segment this screen requires original-photo citation and exactly one visible cited source semantic-role anchor; duplicates, partially occluded or unobservable features are INSUFFICIENT, not absent. Actual current GLB segment hulls and **physical mesh node index ownership** come from `realized-projection/v1` and are independently recomputed by the installed Host against exact GLB bytes and frozen source-selected camera.

For each pair of independently source-observed identity regions with distinct physical nodes, compute physical projected hull polygon centroids and areas vs source polygon centroids and areas. Clear original left-to-right order (normalized separation >=0.09) and clear relative area ratio (>=1.6x) create **falsifiable constraints**; reversed physical order, collapsed order, swapped area hierarchy or large ratio contradictions yield REWORK. Ambiguous relations, missing current segment, duplicate semantic roles, off-frame geometry or the same physical mesh simultaneously claimed as two source roles yield INSUFFICIENT. `NO_DETECTED_CONTRADICTION` is never `Reference Fidelity PASS`, and no single-view IoU can authorize a semantic identity.

Host `ensureEarlyResemblanceAdmission` uses this check before accepting `surface-topology`; S04b latest authoritative downstream GLB replay repeats it on a changed candidate (never trusts signed shape-stage scores). A source image without identity segmentation remains NOT_APPLICABLE to this **bounded** check, but **not** eligible for QA-03 or final certification on that basis.

## Critical trust limit

The source semantic labels and ROIs are observer-attested in the existing schema, NOT independently recognized by raw-photo pixel classifiers or verified by an independent human reviewer identity. Mere node-name swaps that preserve geometry cannot be semantically disproven with these image-space shapes alone; distinct *physical* mesh-position/size mutations are detectable. No fabricated source-independent authority or aggregate score is granted.

## Acceptance / remaining QA-03 scope

- Actual GLB front/rear basket **size swap**, position reversal, omitted rear physical binding, metadata-only same mesh ownership, stale GLB SHA replay, duplicate/hidden/uncited source ROI, ambiguous source case.
- Nonfixture Host checkpoint does not advance on forged source roles with same mesh; current candidate and original photo digest remain authoritative.
- Node20/22/24 full fast regression, Node24 installed fresh-worker and VC08, exact HEAD review, develop-only merge and postmerge CI required.
- **Not yet solved:** validated original-image role semantics/reviewer provenance, missing structural strut and diamond vs step-through shape topology, source-relative attachment/support relations, relationship with `relational-evidence` full QA-coverage receipt, real photo external worker and final release deep CI. Keep #271/#272/#265 OPEN and S05/S06 next. Stable main v1.2.0 unchanged.
