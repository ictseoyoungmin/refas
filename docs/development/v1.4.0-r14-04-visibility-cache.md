# R14-04 — Shared Visibility and Diagnostic Cache

Status: IMPLEMENTATION CANDIDATE, not a certification upgrade. In v1.4.0 development this is intentionally a separate Python CLI with no new public refas skill instruction or source-fidelity gate. R14-02 serial, R14-03 tiled CPU and v1.3.0 portable exact byte-replay identities remain intact.

## Implemented

- `render_cpu_tiled.render_hero_tiled(..., return_visibility=True)` exposes its **already computed** screen-winner/depth arrays and original normal color/primitive-ID tables. Default return type and all previous CLI outputs are unchanged.
- `render_cpu_visibility.py` performs **one** depth/visibility/raster pass for a registered Hero camera, then derives three opaque diagnostic passes from the same winner buffer: `normal`, `object-id`, and `albedo` (base color only). It does not render beauty/PBR, transparency, textures, scene animations, or certified source resemblance. The underlying R14-03 tiling, clipping, stable depth tie and worker ownership rules remain.
- Output `render-report.json` binds source GLB SHA-256, canonical frame-file SHA-256, canonical frame digest, worker profile/version, per-PNG SHA-256, tile and thread selections, visibility passes executed, real shared visibility evaluation count and cache status. A fresh output directory is required; publication is staged.
- Optional *diagnostic-only* disk cache stores `winner`, `depth`, normal RGB-by-raster-triangle, and source triangle primitive IDs in non-pickle `.npy` buffers. A manifest records each buffer's SHA-256, size, shape and dtype. The content-addressed cache key binds GLB+frame SHA, canonical camera values and frame digest, dimensions, tile size, thread count, Numba/NumPy/Python/machine versions and both worker script SHA-256 hashes.
- On cache hit, raster is not reexecuted and the three images are regenerated from verified visibility arrays and **current** model materials (model decode still occurs). Changed source/frame/camera creates a new key; corrupt file bytes and symlinked cache members are explicitly rejected. Atomic directory publication avoids partial cache entries becoming accepted.
- The cache is not signed by a separate authority. An attacker capable of modifying both cache data and hashes could manufacture a new diagnostic cache; **therefore no cached result can authorize a certificate or source-based claim**. Certified replay still requires the original independent evidence gate.

## Running

```bash
# Optional diagnostic workflow: requires Numba, standard package installs do not.
python3 -m pip install numba==0.65.1

# Generate one real reference-independent organic benchmark fixture.
python3 skills/refas/scripts/benchmark_render_cpu.py \
  --case organic --triangles 10000 --dry-run --save-fixture temp/r14-vis-10k

# First visibility+pass run (cold)
python3 skills/refas/scripts/render_cpu_visibility.py \
  --glb temp/r14-vis-10k/benchmark.glb --frame temp/r14-vis-10k/frame.json \
  --passes normal,object-id,albedo --size 128 --tile-size 32 --threads 2 \
  --max-working-mb 512 --cache-dir temp/r14-vis-cache --out temp/r14-vis-first

# Repeated identical inputs: visibility cache hit, newly materialized PNGs
python3 skills/refas/scripts/render_cpu_visibility.py \
  --glb temp/r14-vis-10k/benchmark.glb --frame temp/r14-vis-10k/frame.json \
  --passes normal,object-id,albedo --size 128 --tile-size 32 --threads 2 \
  --max-working-mb 512 --cache-dir temp/r14-vis-cache --out temp/r14-vis-second
```

For a real production asset substitute its original GLB and source-registered canonical frame. Generated benchmark scenes can test rendering throughput, **not resemblance**. Comparison of PNG hashes, peak RSS and time must use a pinned machine/runner and include cold Numba compilation separately from warmed runs.

## Test and boundary gates

`npm run test:cpu-jit` runs the original R14-02/03 tests and R14-04 tests in Node24 CI with the *optional* Numba wheel installed. Tests cover bit-identical outputs versus separate Normal/Object-ID R14-03 rendering, unchanged PNGs across cache miss/hit, changed-frame key invalidation, corrupt-cache refusal, multiple tile sizes/threads on 12k real strand triangles, unsupported pass/resource refusal, and two CLI runs with SHA-bound output PNGs.

Future work remains: full 8-view coverage, PBR shader parity, certified independent replay/attestation, disk cache GC and independent real 100k/500k/1M performance benchmarks. This prototype must not be misrepresented as complete material/texture fidelity or proof of high-density production SLA.
