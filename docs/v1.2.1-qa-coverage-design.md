# v1.2.1 — Source-to-Asset QA Coverage Contract (QA-01 design)

Status: implementation design on `feat/265-source-bound-qa-coverage`; no certification or runtime behavior is claimed by this document. Owner: `whole-object-certification` for admission, `visual-critique` for source comparison, `assembly` for contact/support. Tracking Issue: #265.

## Falsifiable defect

A user-provided bicycle QA bundle produced a syntactically valid 69-mesh / 43,384-triangle GLB with a source manifest and 8-view render, but project state still reported `head:null`, `checkpointIds:[]`, `certification:null`, and `CHECKPOINT_SOURCE_INTAKE` as the next step. `qa/build-report.json` correctly declared `PROTOTYPE_NOT_CERTIFIED`; complete contact, relational, registered-source comparison and final visual QA were not executed. This demonstrates **an unverified asset can be delivered**, not that RefAs incorrectly certified one.

The demonstration's `--negative-swap` switches part **name-prefix lookups**, not actual GLB geometry. Its ~432px mismatch is a semantic-query test, **not** evidence that a swapped geometry would be blocked. For regression create a real changed GLB candidate while keeping the independent source observation frozen.

The user-provided photo and derivative GLB have not been licensed for public redistribution. Keep them outside the source tree; negative fixtures checked into CI must be independent synthetic geometry.

## Trust boundaries and architecture

- Source identity is established by `source-intake`, not by the GLB author, part labels, generated novel views or generated metadata.
- A read-only trusted **QA coverage evaluator** assembles existing source, checkpoint, candidate, relational, contact, registered-comparison, visual-review, rendering and certification evidence. It does not introduce an alternate certificate, reviewer, resemblance objective, or source inference algorithm.
- A canonical `refas verify --root DIR --asset FILE --profile source-bound-object` returns an immutable observation/report with exact artifact and report SHA-256. It must never mutate a project or certify it.
- QA-01a is deliberately **coverage-inventory only**: contact report bytes, even digest-valid ones, are `INSUFFICIENT` until QA-02 independently replays the typed contact plan/graph/GLB. Therefore an otherwise certified asset may remain `BLOCKED` by QA-01a; this is a conservative incomplete profile, not a claim the existing RefAs certificate is invalid.
- Trusted `whole-object-certification` and a separate **finalized handoff/admission** decision consume this report or reproduce its findings directly. A draft GLB may remain transferable as clearly `uncertified`; a release-grade/certified claim cannot pass a missing required gate.
- Host/final-delivery integration is necessary. Adding a CLI command alone does **not** prevent an agent from shipping an unverified file. The authoritative host/export path must surface the profile outcome.
- Preserve existing certification gates (`assessCertification`, `assessClaimCertification`, `auditProject`) and their exact-byte replay. Do not equate a passing mesh inspector or renderer with source-fidelity closure.
- The coverage report must not self-certify. Candidate-authored `PASS`, hand-written artifact-ref lists, unchecked image ROIs, or worker declarations are never trusted verdict authority.

## Required report fields

```text
schema: refas.qa-coverage-report/v1
profile: source-bound-object
subject:
  projectId, sourceSha256, assetSha256, checkpointId, lineageDigest
checks[]:
  id, owner, required, applicabilityAuthority, status,
  subjectDigest, evidenceDigests[], evaluatorId,
  findings[], reason, validatedAt
decision:
  state: BLOCKED | REVIEW_REQUIRED | ELIGIBLE
  blockingCheckIds[], incompleteCheckIds[]
reportDigest
```

Allowed status domain: `PASS`, `FAIL`, `NOT_RUN`, `INSUFFICIENT`, `NOT_APPLICABLE`.
Use `NOT_RUN` when a required operation/evidence was never invoked, `INSUFFICIENT` when invoked but lacks valid independent source authority/current bytes, `FAIL` when trustworthy current evidence contradicts the contract. `NOT_APPLICABLE` requires a trusted evaluator-derived typed reason and never a worker request alone. `PASS` requires actual validator/current source→asset binding, not a present filename, schema field, or generated score.

## Profile gate inventory

1. **Source:** raw bytes, project-bound manifest digest, source-space context and acquisition provenance.
2. **Geometry candidate:** exact GLB SHA-256 and candidate/selected checkpoint/lineage continuity; `inspectGlb.valid` is only intrinsic validity.
3. **Spatial:** realized GLB VC01–VC07 role-aware evidence, current neutral-clay report and parent-lineage decision.
4. **Relations:** independent source-observed semantic topology/landmarks, `relational-structure`, `semantic-authority`, current discrepancy/barrier and whole-object certification floor.
5. **Contact/support:** realized component/attachment/support reachability or explicit trusted typed non-applicability; never nearest distance alone.
6. **Visual:** source-registered comparison, provenance, meaningful identity-region board and independent review; optional IoU only with at least two independently source-backed registered views and never certification by itself.
7. **Authorization:** current claim/transaction certification readiness and audit; absence of certificate is not silently `PASS`.

## Acceptance and adversarial tests

- A renderable GLB with source manifest but no checkpoints/contact/relations/review yields **BLOCKED** with typed `NOT_RUN` for missing mandatory checks.
- Replacing GLB bytes, swapping source bytes, spoofing `PASS`, forging `NOT_APPLICABLE`, or replaying a stale certificate fails trusted exact-byte evaluation.
- Disconnecting a handle grip/lamp, removing basket support, actually swapping front-large and rear-small basket geometry, replacing step-through with diamond frame, or omitting rear basket must be rejected or marked insufficient by their respective owner.
- Missing independent source semantics or hidden/occluded regions are `INSUFFICIENT` / `UNKNOWN`, not fabricated failures or invented evidence.
- An expressly intentional free/rigid-follow/articulated component passes only if its relation is explicit and verified, not merely because two meshes are near.
- Protected CI includes Node 20/22/24, installed-skill-only fresh-worker, a host delivery attempt, negative artifact mutations, and provenance replay.
- #250 real external model/prompt/reference matrix and #235 external adversarial worker results remain distinct obligations, not replaced by a deterministic QA-01 test.
