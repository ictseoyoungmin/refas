# R14-05D — One-host warm-JIT CPU scaling evidence

Status: **IMPLEMENTATION CANDIDATE; measurements pending**.

R14-05A/B/C previously completed the first real positive-area dense GLB tests
at 100k/500k/1M triangles. The three GitHub jobs landed on **different CPU
models**, and each subprocess compiled Numba afresh. Those cold-JIT wall times
cannot establish per-triangle scaling. R14-05D measures the actual geometry
from three newly seeded GLBs **sequentially on the same runner in a single
Python process**, after an explicit 120-triangle JIT warmup.

## Scope and independent proof

- Implementation: `skills/refas/scripts/benchmark_render_cpu_warm.py`.
- **One GitHub runner and Python process** for all tiers. Do not split
  tri-counts across independent matrix jobs.
- Explicitly warm the exact compiled `_setup`, `_tile_counts`, `_scatter`
  and `_tiles` Numba function signatures on real nondegenerate geometry
  before any measured tier. `jitWarmup` is separate in the report.
- Generate deterministic indexed, nondegenerate strand GLBs (default seed
  12345), load with the *actual GLB parser*, bind the generated registered
  Hero canonical frame and verify the face count.
- Baseline normal visibility raster for every tier (default 100k/500k/1M
  triangles, 160×160, tile32, four workers), repeated 3 times without
  starting new subprocesses. One pass shades normal/object-ID/opaque
  albedo via the existing production diagnostic `_shade_passes` logic.
- On one selected density (default 500k), test the 16/32/64 tile ×
  1/2/4/8 Numba worker matrix (12 combinations, including baseline).
  8 threads may oversubscribe GitHub's four logical CPU cores;
  the report records the machine model, cores and configured max threads.
- The benchmark refuses parity differences in **exact PNG pixel array
  content, winner int64 and depth float64** hashes. It does not merely
  compare a silhouette IoU or selected sample pixels.
- Capture decoded load time and per-call wall time, shader time, the
  setup/bin/raster stage metrics, worker count, tile occupancy, candidate
  pixel tests, and Linux process RSS/VmHWM snapshots.
- The independent earlier cold-JIT [evidence](v1.4.0-r14-05-measured-2026-10-15.md)
  remains separate; never compare that data to new warm-JIT measurements
  without highlighting distinct execution conditions.

## Run without slowing ordinary CI

`.github/workflows/r14-05-warm-matrix.yml` runs ONLY on opt-in
`bench/r14-05d-*` branch pushes (or manual workflow_dispatch after it
exists on default branch). Review the R14-05D PR and merge to
`develop/v1.4.0` first; then branch `bench/r14-05d-YYYYMMDD` at the
exact merged commit and push a marker-only commit to trigger the workflow.
Never merge the marker or amend source during evidence collection.

Equivalent local command with optional Numba 0.65.1 installed:

```bash
NUMBA_NUM_THREADS=8 OPENBLAS_NUM_THREADS=1 python3 \
  skills/refas/scripts/benchmark_render_cpu_warm.py \
  --triangles 100000,500000,1000000 --matrix-count 500000 \
  --case strands --seed 12345 --size 160 \
  --baseline-threads 4 --baseline-tile 32 \
  --thread-matrix 1,2,4,8 --tile-matrix 16,32,64 \
  --repeats 3 --max-working-mb 1024 \
  --out temp/r14-05d/same-host-warm.json
```

The JSON artifact is `measurement-only` and explicitly has
`certificationEligible: false`. It reports a cumulative process
high-water mark, **not per-tier peak RSS**: its value can only stay
the same or increase as successive tiers execute. JIT warmup is
excluded from measured samples, but camera-space allocation/preparation
inside each diagnostic renderer call is included. It is not a pure
raster-only microbenchmark.

## R14-05 open blockers

- Results must first be **actually run, inspected and recorded**. Source,
  renderer profile, runner CPU and pixel/winner/depth parity must remain
  bound to the evidence.
- A real production Monster Bed GLB and registered frame must be supplied
  or located before making any source-asset performance/fidelity claim.
- Canonical multi-view shape/material/PBR evaluation is **not** part of the
  current 160px Hero diagnostic worker, and cannot be inferred from PASS.
- If a real asset is unsupported, surface a typed limitation; never silently
  reduce triangle count, generate a fake source or certify a proxy.
- A later R14-05E can target measured measured CPU cost centers, then run the same
  fixture hash and geometry-golden parity tests before closure.
