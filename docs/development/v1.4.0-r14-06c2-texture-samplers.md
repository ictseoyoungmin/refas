# R14-06C2 — glTF PNG sampler and color-space contract (LOD 0)

Status: **IMPLEMENTATION CANDIDATE — PRE-MERGE CI AND EVIDENCE REQUIRED**.
This is a deliberately scoped material-preview feature, not a complete
material/PBR implementation or source resemblance certification.

## Supported (explicit only)

- **Unmodified indexed source GLB**, embedded PNG `baseColorTexture`,
  `TEXCOORD_0`, source-derived perspective-correct barycentric interpolation
  from R14-06B. glTF UV (0,0) maps to **upper-left image corner**.
- Source glTF `baseColorFactor` (default white), original `COLOR_0`
  (linear RGB), and per-fragment base-color texel multiplied in **linear
  RGB**. PNG RGB is sRGB: **decode each texel using piecewise sRGB inverse
  BEFORE linear/bilinear filtering**, never filter encoded sRGB directly.
  The alpha of a PNG on a declared OPAQUE material is ignored as prescribed.
- Sampler `NEAREST (9728)` and `LINEAR (9729)`, base mip level **0**
  only, using correct half-texel-center coordinates
  `x=u*width-0.5, y=v*height-0.5` for bilinear. `REPEAT (10497)`,
  `CLAMP_TO_EDGE (33071)`, `MIRRORED_REPEAT (33648)` supported
  independently in U/V, including NPOT images.
- Because the glTF specification permits an implementation-defined
  filtering choice when sampler filtering is unspecified, v2 uses the
  **explicit pinned LINEAR level-0** fallback. This is a preview
  implementation policy, not a spec-mandated renderer default.
- Independent typed fail-closed for any **declared mipmap filtering**
  (9984–9987), simultaneous contradictory min/mag filters when the
  renderer has not computed a footprint/LOD, unsupported TEXCOORD_1,
  extensions, external/JPEG/data-uri images, invalid PNG, unknown wrap,
  missing/invalid UV and oversized image budget (2,097,152 texels/image).
  Material feature validation is performed before the expensive
  visibility kernel; the common v1 loader stays untouched.

## Authority and versioning

Worker identity changes to
`RefAs PBR v2 Opaque Preview/0.2.0-texture-lod0`; normal/no-texture
render results retain their existing visible-only shading numerics,
but new source input classes have new behavior and must not reuse the
old 0.1.0 prototype identity. `preview-report.json` still uses
`refas.pbr-v2-material-preview/v1`, records `claimScope:
material-preview-only`, `certificationEligible: false`,
source/frame/output digests, supported and unsupported material
categories, and counts of texture-shaded pixels. It is **never**
a trusted PBR report or an independent validation certificate.

R14-06C2 intentionally leaves all other glTF material path features
(IBL, normals/maps, alpha MASK/BLEND, emissive, metallic-roughness
textures, filtered mipmaps, LOD derivatives and extensions) **unsupported**
and must not claim they render accurately. R14-06D/E/F remain open.

## Independent adversarial tests

`tests/test_render_pbr_v2_texture.py` checks:

1. A deliberately contrasting two-texel pattern has linear sampled RGB
   0.5, **not** encoded-space 0.5 decoded to 0.214;
2. glTF upper-left NEAREST, REPEAT seam, clamp and MIRRORED_REPEAT
   including UV beyond the 0..1 range;
3. All four mip filtering modes, mismatched explicit min/mag, TEXCOORD_1,
   unknown wraps and external PNG fail closed;
4. Per-fragment `baseColorFactor × COLOR_0 × sampledBaseColorTexture`
   against a separate hand-computed barycentric color oracle with
   occlusion/background unchanged;
5. A real, generated **indexed glTF 2.0 binary** with embedded RGBA PNG,
   TEXCOORD_0 accessor, sampler, factor and shader four passes: output
   source SHA, PNG hashes, sampled pixel count, no certifying flag.

Run the new focused test in Node24's optional Numba CI only.
Do not add full private Monster Bed or 1M material stress runs to
normal CI. The real original Monster Bed already has COLOR_0 but does
**not** use baseColorTexture; unchanged its full-asset path should
be checked with the exact input/preview SHA in opt-in R14-06D.
