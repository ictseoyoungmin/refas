# RefAs v1.4.0 — Release readiness and scoped claims

## Intended release boundary

Version 1.4.0 promotes the performance, reuse, and material-preview changes developed in `develop/v1.4.0`: shared visibility and cache, compiled/tiled CPU rendering, PBR-v2 supported material/texture paths, exact-input evidence, and optional external Blender Cycles diagnostics. Stable v1 renderer/camera evidence namespaces and published tags remain unchanged.

**Not part of this release:** source-photo-registered Hero/multiview likeness certification (R14-06F), generalized photometric CPU/Cycles equivalence or complete glTF PBR material coverage, calibrated real-world physical truth, or universal agent model-making success. Unsupported features keep explicit typed refusals or non-certifying previews. Monster Bed source and camera evidence remain private and are not committed or sent to a public CI runner.

## Frozen release acceptance

- Exact release package/runtime/plugin version: `1.4.0`; README and CHANGELOG describe bounded runtime capabilities.
- New E2/v2 offline private original-asset evidence is **diagnostic only** and an unregistered camera; its contract negative tests run in the normal optional Node24 Python test stage. The historical provisional frame is **not** claimed to have been replayed.
- `npm test`, `npm run test:python`, `npm run check`, `npm run dogfood`, scoped PBR/geometry/assembly fixtures and `npm run release:audit` must pass at the same verified head.
- The `develop/v1.4.0` promotion candidate must pass Node20/22/24 and a full Node24 `[full-qa]` deep path with the release audit and clean package-install/upgrade smoke, rather than inferring success from green Tier1 jobs with Tier2 marked SKIPPED.
- Before a tag can be published, the merge commit on current `main` must complete full Node20/22/24 postmerge push CI including `Complete dogfood` and `Release audit` step SUCCESS.
- GitHub `v1.4.0` tag and Release only through the existing protected manual `Publish verified release` workflow on `main` with the exact SHA and explicit `PUBLISH` confirmation. No automatic commit-message publication path; no npm publish claim.
