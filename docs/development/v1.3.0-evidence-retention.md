# v1.3.0 observation retention and cache provenance

The current observation manifest is an atomic pointer to active evidence. Derivatives excluded from that manifest carry SHA-256 tombstones and are unavailable as active observation aids.

Physical snapshot files are immutable historical data, not an automatic garbage-collection target. Earlier snapshots may be cited by checkpoints, model edits, observation records or external agent artifacts. The extraction/review commands retain prior snapshots and report zero physically deleted files. A future explicit GC operation must enumerate and validate all references and provide a reviewable deletion plan before reclaiming files.

Cache reuse additionally checks source-manifest file SHA-256; equal image pixels with different signed context are distinct extraction provenance.

Previously discarded output may be assessed again as discarded. To use it again as evidence, regenerate the derivative from its original source and make a new active manifest. Observations, model-impact statements and source-bound certification remain distinct authorities.

This retention change is intentionally conservative. It increases disk usage on projects with many revisions, and the operational cleanup interface is postponed until complete-reference authorization exists.
