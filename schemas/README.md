# Public schemas

These Draft 2020-12 schemas describe the immutable artifacts emitted by the canonical runtime in `skills/refas/scripts/lib/`. Constructor input templates live in `skills/refas/assets/templates/`; constructors normalize those inputs and add digests, policies, metrics, and derived fields before an artifact conforms to its public schema.

Runtime validators remain authoritative for semantic invariants that JSON Schema cannot express compactly, including hierarchy ancestry, digest recomputation, registration invertibility, unique shared adjacency, acyclic occlusion, capability lineage, exact artifact-byte recovery, independent-reference certification, complete view and gate sets, blocking-finding refusal, independent PBR report binding, and renderer material support.

`canonical-object-frame.schema.json` also documents the editable frame input consumed directly by the renderer. The renderer remains authoritative for orthonormality, handedness, finite coordinates, exact GLB part-name resolution, and the canonical frame digest.

`canonical-edit-intent.schema.json` records the edit owner, hierarchy scope, edit class, canonical upstream bindings, realization operations, and GLB mutation boundary. The runtime is stricter than the schema: semantic shape edits must originate in construction state and rebuild the realized GLB; pose may directly change only node/joint transforms while mesh/accessor bytes remain immutable; appearance state precedes rebaking; controlled mesh fusion/welding/cleanup/optimization belongs only to finalization.

`attachment-semantics.schema.json` records explicit attachment modes and owner/dependent direction before propagation or contact validation. The runtime requires every declared entity to have exactly one primary mode (including `FREE`), enforces mode-specific owner cardinality, and rejects unknown owners, self attachment, duplicate IDs, and ownership cycles. The semantic graph itself does not mutate geometry or authorize closure.

`logical-fusion.schema.json` derives deterministic logical bodies only from `FUSED` attachment relations while keeping semantic parts separately addressable. `logical-fusion-invalidation.schema.json` binds member edits to the exact attachment/fusion digests and expands a changed fused member to the complete invalidated logical body. Runtime validation reproduces both artifacts, forbids physical mesh mutation at this stage, leaves non-fused dependents for attachment propagation, and does not grant closure authority.

`surface-anchor-set.schema.json` records owner-local surface frames for surface-following attachment relations. Each anchor binds a declared owner to a semantic patch, triangle, barycentric coordinate, tangent hint, normal offset, exact owner geometry/surface digests, and local rebind bounds. `surface-anchor-rebind.schema.json` binds the previous and next anchor sets and records deterministic unchanged/rebound results. Runtime rebind stays inside the same semantic patch, enforces anchor-local distance and normal-deviation bounds, rejects world-coordinate-only canonical locators, and never moves dependent geometry or grants closure.

`attachment-follow-state.schema.json` stores the canonical one-owner propagation state for `RIGID_FOLLOW` and `SURFACE_OFFSET`. Rigid follow preserves a baseline owner-relative rigid frame; surface offset binds the exact surface-anchor set plus a subject-local contact frame. `attachment-follow-report.schema.json` records explicit owner world frames and deterministic subject target frames. Runtime validation rejects unsupported multi-owner relations, missing owner frames, malformed rigid frames, and tampering; these artifacts calculate targets but do not mutate mesh bytes, recursively order a dependency graph, or grant closure.

`parameter-fit-plan.schema.json` and `parameter-fit-report.schema.json` define owner-local joint geometry search. The runtime additionally enforces bounds, protected-regression semantics, deterministic trial order, bounded population initialization (`initializationAttemptBudget` plus finite integer-space cardinality), exact plan/report digests, and candidate/render byte verification.

The optional shape-repair backend consumes those same plan/report contracts and derives its objective measurements from digest-bound realized projection proofs; it binds each actual render report and hero image to the candidate GLB, the renderer-recorded hero camera values normalized and digested by the JavaScript runtime, and frame, rejects unevaluable objectives, and does not introduce a second evidence schema or mix material appearance terms into geometric segment IoU. The first trial is also required to carry the exact baseline asset SHA-256 before it can establish baseline measurements.

`camera-fit`, `pose-fit`, `appearance-fit`, `lighting-fit`, and `macro-fit` are owner-local fitting ledgers. Camera and pose preserve the geometry representation (pose checks the exact BIN chunk); appearance and lighting bind a frozen geometry/frame digest. `geometry-backend` and `representation-capacity` describe landmark cages, longitudinal guides, section-profile lofts, and explicit expressive-capacity blockers. `perceptual-discrepancy` is deterministic model-free evidence with candidate-ranking-only authority. `benchmark-matrix` binds external source paths and requires visually justified closure across at least two independent-reference classes before a reusable capability can close.
