### Fast lane: mandatory on every PR and develop/v1.2.1 push
- Node 20/22/24 **full existing `npm test` suite** (not a smoke-only shortcut): tests include source-photo/GLB raster mutation, typed missing-source, authenticated current render, and VC05/VC06/VC07/VC08 regressions.
- Python syntax, instruction graph, product boundary and plugin/instruction integrity.
- Node24 **installed public-contract fresh-worker** and **VC08 adversarial dogfood** (short essential independently installed boundary).
- Auto-cancel obsolete PR/develop runs on a new push; never auto-cancel main release runs.
- No relaxing production gates and no rewriting evidence into signed self-PASS; keep test-fixture vs actual-photo restrictions.

### Deep lane: before release/promotion, manually and periodically
- Heavy long-running Dogfood, full multiview baseline, structural/assembly/render/texture/PBR/parameter-fit and complete release audit.
- In `ci.yml`, **main push always runs full suite**. A develop/v1.2.1 push carrying exact marker `[full-qa]` also runs full suite; use this for milestone-wide explicit verification while keeping daily development fast.
- `ci-deep.yml` provides manual branch/ref selected full Node24 and weekly deep suite **once installed on the repository default branch**. Until default-branch activation, `[full-qa]` develop push is the effective deep-run trigger; do not assume a scheduled workflow exists yet.
- Preserve exact-head Node 20/22/24 *fast* pass before merge; require deep passing status for S03 closure, external real-photo dogfood, v1.2.1 release/promotion and after significant renderer/architecture changes. Fast pass alone cannot prove real-photo Reference Fidelity or Game Ready.
- Stable main v1.2.0 remains unchanged. Any version promotion requires complete original full-grade gate, external evidence, and exact postmerge audit.
