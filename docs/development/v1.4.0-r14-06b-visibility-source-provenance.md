# R14-06B — Separate PBR v2 source-provenance visibility vertical slice

Status: **implementation candidate**, no certified material appearance. Reviewed
architecture: [R14-06A](v1.4.0-r14-06-independent-pbr-v2-design.md).
The v1 Python PBR raster, R04 neutral-clay profile, v1 PBR report schema and
registered replay verifier are unchanged.

## New opt-in diagnostic worker

`skills/refas/scripts/render_pbr_v2_visibility.py` provides a **separately
compiled Numba visibility kernel**, not a faster wrapper for the old v1
Python-per-triangle PBR algorithm. The experimental profile is
`RefAs PBR v2 Visibility/0.1.0-prototype`. It returns:

- Depth float64, stable raster winner ID, stable **original indexed GLB
  source triangle ID**, primitive-by-source-triangle map, and **three float64
  perspective-correct weights referring to the original un-clipped source
  triangle vertices** for each covered pixel.
- Near-plane Sutherland–Hodgman clipping, including two-fan output for
  triangles crossing the near plane. Each generated vertex carries exact
  three-component source-vertex provenance, which the raster stage
  perspective-correctly combines at the winning depth sample.
- Deterministic tile counts, prefix sums, stable scatter and independent
  tile ownership via Numba `prange`, with bounded candidate pixel rectangles,
  consistent top-left edge rules, z-testing and stable winner priority.
- Fixed per-frame source triangle and primitive ID order, preflight memory
  and bin limits, typed refusal of invalid index/NaN geometry, missing
  registered Hero, non-triangle/morph/animated source geometry or MASK/BLEND
  materials.
- Diagnostic **array** outputs only. No beauty/albedo PNG, no implicit PBR
  feature support, no source photo similarity, no v1 PBR report, and no
  certification. A frame registrationDigest field by itself is untrusted;
  the user-supplied provisional Monster Bed camera is not source registered.

Unlike the old diagnostic raster, the v2 output intentionally retains
per-pixel source-vertex weights to support future metallic-roughness,
COLOR_0, UV and normal interpolation without repeated rasterization.

### Diagnostic CLI

```bash
NUMBA_NUM_THREADS=4 python3 skills/refas/scripts/render_pbr_v2_visibility.py \
  --glb work/monster_bed_v4.glb \
  --frame work/diagnostic-frame.json \
  --out work/v2-visibility-diagnostic \
  --size 160 --tile-size 32 --threads 4 --max-working-mb 1024
```

The input GLB must be unmodified and may remain private outside the repo;
report SHA-256 binds its bytes and frame bytes. Output is non-certifying
`refas.pbr-v2-visibility-diagnostic/v1`, three NPY data arrays plus report
and four exact buffer digest commitments. Refuse an existing destination
rather than mixing stale output with a new capture.

## Independent acceptance oracle

Focused `tests/test_render_pbr_v2_visibility.py` uses a distinct
**3D ray/triangle linear-algebra intersection oracle**, rather than
recomputing the new screen-edge raster formula, to check:

1. Source-triangle barycentric weights and depth of a triangle crossing
   `z=0.01`, including an original vertex behind the near plane.
2. Source ID stable priority of equal-depth overlapping geometry, and
   exclusion of fully behind-near triangles.
3. Tile and available worker-thread exact buffer SHA parity across 16/32/64
   tiles and 1/2/4 threads, including near-plane fan generation.
4. Invariance of geometric visibility when material COLOR_0 or base color
   changes; source-material appearance is a **separate** R14-06C gate.
5. Small actual seeded GLB and registered diagnostic frame passed through
   an independent process with arrays/report SHA checked; type refusal on
   resource limits and output overwrite.

`npm run test:cpu-jit` runs this targeted suite in the existing Node24
optional-NUMBA lane after established CPU diagnostic regressions. **Do not**
add full 900k Monster Bed CPU rerenders to normal PR CI.
