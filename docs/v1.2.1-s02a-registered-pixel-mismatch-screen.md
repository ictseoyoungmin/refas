# RefAs v1.2.1 — S02a registered original-pixel mismatch screen

Parent [#272](https://github.com/ictseoyoungmin/refas/issues/272) (P0). Base `develop/v1.2.1@7f71a5d5b8c30d9a0ff72bee3633387b0163a43a`. This is a narrow **S02a** slice, not S02 or reference fidelity completion.

## The missed error

The existing registered comparison tool digested original image and reported render frame, warped the original to the selected registration, and estimated foreground coverage and outer bounding boxes. A wrong interior silhouette, negative-space slot or misplaced equal-area mass can have **identical bounding rectangle and foreground pixel count**, while macro 3D anchor reprojection RMSE is zero. This failure class must raise a contradiction rather than allowing a visually false asset through just because the existing numbers look good.

## Implementation

- The existing `compare_registered.py` operates directly on registered original image pixels and current report-bound rendered frame pixels, not a worker-authored `reference-geometry` contour. It records a new `scopes[].metrics.perceptual.pixelShape` **derived observation aid**: source-only and render-only pixel counts and fractions computed from independently extracted foreground masks.
- The conservative corner-background segmentation screen marks a scope `INSUFFICIENT` where image dimensions are too small, corner colors are not uniform or object occupancy is too small/large. Such data must not be treated as evidence of likeness. A stable matte source/render background plus bounded foreground is `USABLE` for **contradiction screening only**.
- The existing `findComparisonContradictions` now reports `whole-pixel-shape-screen` / `silhouette-mismatch` when both source-only and render-only fractions are substantial (>0.28). This detects divergent placements of visible material or internal voids that escape overall area/bounds checks. It is a **veto / requires a typed finding**, never automatic PASS.
- `validateRegisteredComparison` validates authority tags, bounded numeric fractions and counted pixels when the observation aid is present. Older reports still parse as legacy criticism evidence (not proof of S02 completion); digest changes are bound through the existing report digest and source/render identity checks. No single-view IoU is computed or used.
- Tests create actual 64×64 raster files: a positive matching source/render and an adversarial original with left internal negative space versus the comparison render with right internal negative space. Both retain exactly equal foreground counts and bounding boxes; the new pixel screen raises the contradiction even with zero anchor reprojection error.

## Trust boundary and residual gaps

**This is not an independent GLB renderer authenticity gate.** Current registered comparison binds original source SHA and a `render-report`'s frame SHA and GLB asset SHA, but does not independently re-render the current GLB with the frozen source camera inside the certifying worker. A malicious worker could publish unrelated image bytes with self-consistent reported hashes. S02b must independently replay the GLB-to-frame render provenance, then compare pixel-derived contours/occlusions in current camera space; S03 covers head/face/torso/shoulder identity negatives. An ordinary photo with complicated background often returns `INSUFFICIENT`; do not silently treat it as visual PASS.

The source-visible geometry is not conclusively extracted or semantically interpreted by this tool. Source observation must not be inferred from labels, manually authored contours, a rendered GLB or registration points. Full P0 and certification still block until an independently observed source-to-current-render trust chain exists. Parent issue #272 stays OPEN and main stable.
