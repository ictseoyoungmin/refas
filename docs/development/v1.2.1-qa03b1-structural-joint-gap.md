## Failure and physical authority

In the original source a strut and support mount visibly join at an explicit observed boundary. The actual candidate GLB may have a gap at that interface while the source-observed part polygons and their realized envelopes remain within S03a broad tolerances and all candidate GLB files are valid. The independent physical geometry evaluation uses `referenceGeometry.interfaces` already recorded before modeling, not string-matching GLB node names or caller-authored contact PASS.

The screen reads source-cited `importance: macro|identity`, `separation:explicit`, `visibility:visible` interfaces of kinds `joint-boundary`, `contact-boundary` or `necked-transition`, and requires:
- Subject/object source-visible segment polygons plus interface boundary from exact original source.
- Distinct actual mesh-node index ownership in `derivedSegments`; projection is created/replayed from exact signed GLB bytes and frozen source camera.
- Source interface polyline reasonably near both source part edges (otherwise INSUFFICIENT).
- A directly measured minimal projected **actual GLB hull-to-hull mesh gap**. A gap larger than 0.032 normalized image width produces REWORK. No source citation, unknown/occluded joint, overlapping semantic ownership, missing physical segment, or source boundary inconsistency → INSUFFICIENT. No observed explicit interface → NOT_APPLICABLE for this bounded check, never equivalent to full QA-03 source-fidelity PASS.

This is integrated at the nonfixture Host shape→surface pre-detail admission and S04b changed-downstream GLB replay. A clear source joint with separate physical projected meshes yields only `NO_DETECTED_CONTRADICTION`, **not** 3D contact/weld/load-bearing proof, and cannot authorize Reference Fidelity. Projected hull overlap could hide a 3D depth gap; the installed QA-02 realized 3D contact/attachment gate remains separately mandatory.
